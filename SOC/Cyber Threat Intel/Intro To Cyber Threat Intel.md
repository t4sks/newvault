CTI (Cyber Threat Intelligence) - концепт который помогает определять какие реальные последствия могут возникнуть при траиже инцидента, и помогает определять какие запросы смотреть первыми и какие несут реальную опасность

# От голых данных до используемых в CTI 
Литература по информационной безопасности отлечает 
- data
- information 
- intellegence
Три этих термина часто затираются в повседневных взаимодействиях. Разберемся в чем их отличие:

| Layer        | Определение                                                          | Alert-queue пример                                                        | SOC L1 действие           |
| ------------ | -------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------- |
| Data         | Необработанный наблюдаемый параметр                                  | `45.155.205.3 :443`                                                       | зафиксировать артефакт    |
| Information  | Данный плюс актуальное описание                                      | IP зарегистрирован на Hetzner, первое упоминание зафиксировано 2023-07-14 | Записать атрибуты         |
| intelligence | проанализированная информация отвечающая на вопрос "Что это значит?" | IP принадлежит текущему Bumblebee C2, заблокировать незамедлительно       | Эскалировать или подавить |
Аналитик L1 отвечает за создание используемых артефактов и их обогащения пока они не станут квалифицироваться как intelligence или демонстрировать что они никогда не будут такими. Это реализуется за счет обогащения (enrichment): быстрая, методичная проверка публичных коммерческих и внутренних ресурсов чтобы указать на происхождение, поведение и значение

Во время передачи данных в разведку аналитикам необходимо знать еще три ярлыка.

- Indicator of Compromise (IOC): доказательства нарушения такие как C2 адрес в логах
- Indicators of Attack (IOA): вредоносная активность, такая как запуск с помощью powershell неизвестного сервиса 
- Tactics, Techniques and Procedures (TTP): Подробные методики противника, выраженные в идентификаторах и описаниях MITRE ATT&CK

# Файловый и Hash TI
## Filepath Analysis
Пути к файлам и имена похожи на улики на месте преступления, они раскрывают поведение злоумышленника. Злоумышленники могут использовать разные участки диска чтобы скрыть свои действия и уменьшить видимость.

- `C:\` - системный диск, может быть общей целью для механизмов закрепления
- `C:\Users\Public` - Профиль может обеспечить межпользовательский доступ к активированным инструментам противника
- `C:\Users\Public\Public Downloads` предоставляет высоко загруженную директорию которая зачастую позволяет обойти строгий мониторинг

Кроме того злоумышленники могут использовать другие паттерны вредоносного ПО, например

- Использование временных директорий таких как `C:\Windows\Temp` для эфемерных полезных нагрузок
- Размещение payloads в доступных для записи системных путях таких как `C:\ProgramData` для тихого закрепления

### Эвристические признаки в именах фалов
Атакующие так же знают как модифицировать имена файлов для избегания обнаружения через имплементацию различных типов эвристических индикаторов включающих в себя

- Двойные разрешения - `invoice.pdf.exe`, который использует настройки Windows по умолчанию скрывающие расширение файлов
- Имитация системных двоичных файлов - имя файла, например `scvhost.exe`, злоупотребляет знанием пользователем основных системных процессов. Защитникам следует включать в список разрешенных мест расположения системных процессов а не отдельных имен файлов
- Строки с высокой энтропией - файл с именем `jh8F21.exe` означает что файл скорее всего был сгенерирован автоматически. Так работают упаковщики полиморфные генераторы - каждый экземпляр malware получает уникальное имя, чтобы обойти сигнатурный детект. Характерно для массовых фишинговых компаний.
- Маскировка - имя `backup-2300.exe` сливается с обычными файлами резервного копирования не вызывает подозрений. Второй вариант это замена одного символа, которая может обойти обнаружение выглядя визуально легитимным для обычного пользователя 

Так как злоумышленники могут менять имена файлов мы можем сравнивать их по хэшу однозначно с точностью до бита

```
Command prompt: certutil -hashfile bl0gger.exe SHA256  
  
PowerShell: Get-Filehash -Algorithm SHA256 bl0gger.exe
```
