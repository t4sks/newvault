# Обзор ведения журнала
Каждый раз когда вы запускаете программу или создаете файл, или просто входите в систему на своем компьютере, событие обрабатывается операционной системой. Затем операционная система может зарегистрировать событие добавив в журнал строку с указанием времени, деталей действий и пользователя, выполнившего действие. Каждое зарегистрированное событие называется `log` и правильное ведение журнала гарантирует что вся активность пользователей системы будет зафиксирована, что помогает SOC в следующих задачах:

- Incedent Response: журналы могут показать, когда и как произошла атака
- Threat hunting: Логи позволяют искать признаки вредоносной активности
- Alert and Triage: Журналы являются основой любого правила оповещения или обнаружения

# Анатомия логов
Windows предоставляет огромные возможности для логирования, но требует знаний для чтения и понимания логов.
Базовое хранилище логов находится в `C:\Windows\System32\winevt\Logs`, все что пишется через Event Tracing for Windows и Event Log Service попадает сюда, аналог `/var/log` в Linux 
![[Pasted image 20260608191314.png]]

Каждый файл EVTX соответствует определенной категории журналов. Например логи приложений (Application Logs) содержат события, зарегистрированные пользовательскими приложениями, такими как веб сервер IIS или база данных MS SQL, а журналы безопасности (Security Logs) фиксируют такие события как попытки входа в систему, активность процессов и управление пользователями
# Чтение журналов
Используем `Event Viewer` для вызова используем `Win+R` и вписываем `eventvwr`, и нажимаем Enter. 
`Event Viewer` состоит из следующих компонентов
1. Источник логов(Log Source): Каждый EVTX файл соответствует одному элементу на левой панели
2. Список логов(Log List): Каждая отображаемая строка представляет собой отдельное событие содержащее несколько свойств, по которым можно выполнить сортировку:
	- Keywords: в некоторых случаях указывает было ли успешно действие
	- Отметка времени: когда произошло событие и сами логи(Системное время а не UTC)
	- EventID: уникальный номер для события(Например ошибка входа 4625)
3. Log  Details: фактическое содержимое журнала в текстовом формате XML
4. Filters Menu: используйте `Filter Current log` и `Find` для фитрования всех логов

## Структура User Managment Events 
Все пользовательские события имеют похожую структуру и могут быть разбиты на три части: Кто сделал действие(субъект, Subject), кто был целью (Object, объект), и какие точные изменения были сделаны(детали Deatails)

1. Субъект (Subject): аккаунт который совершает действие. Обратите внимание на поле `Logon ID` - мы можем использовать для сопоставления события с предшествующим событием входа 4624
2. Объект (Object): это может быть названо по разному в зависимости от Event ID, но означает одно, цель совершенного действия
3. Детали (Details): Целевая группа для 4732 и 4733, или новых атрибутов пользователя таких как полное имя или срок действия пароля для 4720
