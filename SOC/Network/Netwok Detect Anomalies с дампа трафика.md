# Nmap сканирование
Nmap умеет сканировать 
- TCP connect скан
- SYN скан
- UDP скан

Для выявления активности очень важно понимать как работает Nmap, однако без использования фильтров невозможно понять детали сканирования
## TCP флаги для поиска в nmap

| **Notes**                                                   | **Wireshark Filters**                             |
| :---------------------------------------------------------- | :------------------------------------------------ |
| Global search                                               | `tcp`<br>`udp`                                    |
| Only SYN flag                                               | `tcp.flags == 2`                                  |
| SYN flag is set. The rest of the bits are not important     | `tcp.flags.syn == 1`                              |
| Only ACK flag                                               | `tcp.flags == 16`                                 |
| ACK flag is set. The rest of the bits are not important     | `tcp.flags.ack == 1`                              |
| Only SYN, ACK flags                                         | `tcp.flags == 18`                                 |
| SYN and ACK are set. The rest of the bits are not important | `(tcp.flags.syn == 1) and (tcp.flags.ack == 1)`   |
| Only RST flag                                               | `tcp.flags == 4`                                  |
| RST flag is set. The rest of the bits are not important     | `tcp.flags.reset == 1`                            |
| Only RST, ACK flags                                         | `tcp.flags == 20`                                 |
| RST and ACK are set. The rest of the bits are not important | `(tcp.flags.reset == 1) and (tcp.flags.ack == 1)` |
| Only FIN flag                                               | `tcp.flags == 1`                                  |
| FIN flag is set. The rest of the bits are not important     | `tcp.flags.fin == 1`                              |
## TCP Connect Scans
Краткое описание сканирования:
- Основывается на трехстороннем рукопожатии(необходимо завершить процесс рукопожатия)
- Обычно выполняется с помощью команды nmap -sT
- Используется непривилегированными пользователями
- Обычно размер окна превышает 1024 байта, поскольку запрос ожидает некоторые данные из за особенностей протокола

| ---------------------------------------- | ---------------------------------------------------------- | --------------------------- |
| - SYN --><br>- <-- SYN, ACK<br>- ACK --> | - SYN --><br>- <-- SYN, ACK<br>- ACK --><br>- RST, ACK --> | - SYN --><br>- <-- RST, ACK |

# ARP Poisoning/Spoofing (A.K.A. Man In The Middle Attack)
ARP Poisoning(также известная как подмена ARP пактов или атака "Человек по середине") - это тип атаки, который включает в себя подавление/манипулирование(jamming/manipulating) сетью путем отправки вредоносных ARP пакетов а шлюз по умолчанию. Конечная цель это манипулировать таблицей IP адресов и MAC адресов и перехватывать трафик целевого хоста

Существует множество инструментов для проведения ARP атак. Однако суть атаки статична, поэтому обнаружить такую атаку легко зная алгоритм работы ARP и используя навыки работы с WireShark

Анализ ARP вкратце:

- Работает в локальной сети
- Обеспечивает связь между MAC адресами не является безопасным протоколом
- Не является маршрутизируемым протоколом
- Не имеет функций аутентификации
- Распространенные шаблоны: запрос и ответ, объявление и пакеты с широковещательной рассылкой

| **Notes**                                              | **Wireshark filter**                                                     |
| ------------------------------------------------------ | ------------------------------------------------------------------------ |
| Global search                                          | `arp`                                                                    |
| **"ARP" options for grabbing the low-hanging fruits:** |                                                                          |
| Opcode 1: ARP requests.                                | `arp.opcode == 1`                                                        |
| Opcode 2: ARP responses.                               | `arp.opcode == 2`                                                        |
| **Hunt:**Arp scanning                                  | `arp.dst.hw_mac==00:00:00:00:00:00`                                      |
| **Hunt:**Possible ARP poisoning detection              | `arp.duplicate-address-detected or arp.duplicate-address-frame`          |
| **Hunt:**Possible ARP flooding from detection:         | `((arp) && (arp.opcode == 1)) && (arp.src.hw_mac == target-mac-address)` |

# Туннелирование трафика ICMP и DNS

> [!NOTE] Туннелирование трафика(Или Port Forwarding)
> Это передача данных или ресурсов безопасным способом в сетевые сегменты и зоны. Оно может использоваться для потоковых данных "из интернета в частные сети" и "из частных сетей в интернет". При этом используется процесс инкапсуляции для сокрытия данных, поэтому передаваемые данные выглядят естественно, но содержат конфиденциальные пакеты данных и безопасно доставляют в конечный пункт назначения

Туннелирование обеспечивает анонимность и безопасность трафика. Поэтому оно широко используется в корпоративных сетях. Однако поскольку оно обеспечивает значительный уровень шифрования, злоумышленники используют туннелирование для обхода периметров безопасности, используя стандартные доверенные протоколы, применяемые в повседневном трафике такие как ICMP и DNS. Поэтому важно уметь обнаружить аномалии ICMP и DNS
## ICMP анализ

> [!NOTE] ICMP
> Протокол управления интернет сообщениями. Предназначен для диагностики и сообщения о проблемах сетевой связи. Он широко используется для отчетности об ошибках и тестировании. Поскольку это доверенный протокл сетевого уровня иногда он используется для DoS, так же злоумышленники используют его для эксфильтрации данных и туннелирования С2

Обычно ICMP туннели представляют собой аномалии появляющиеся после выполнения вредоносного ПО или эксплуатации уязвимости. Поскольку пакеты ICMP могут передавать дополнительную нагрузку данных, злоумышленники используют этот раздел для эксфильтрации данных и установления соединения С2. Это могут быть данные TCP,HTTP или SSH. Протоколы ICMP представляют отличную возможность для передачи дополнительных данных, но имеют недостатки. Большинство корпоративных сетей блокируют пользовательские пакеты и требует прав администратора для создания пользовательских пакетов ICMP

Большой объем трафика ICMP или аномальные размеры пакетов являются индикаторами туннелирования ICMP. Тем не менее злоумышленники могут создавать собственные пакеты соответствующие стандартном размеру в 64 байта, поэтому обнаружение подобных туннельных атак по прежнему затруднительно. 

| **Notes**                                                                                                                             | **Notes**                |
| ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| глобальный поиск                                                                                                                      | `icmp`                   |
| Для быстрого результата проверяйте<br>- Длину пакетов<br>- ICMP адрес назначения<br>- Признаки инкапсулированного протокола в пейлоад | `data.len > 64 and icmp` |

## DNS анализ

> [!NOTE] DNS
> Domain Name System - разработана чтобы конвертировать домены в IP и наоборот. Это важная часть вебсервисов, она широко используется и пользуется доверием, поэтому ее часто игнорируют. Из-за этого злоумышленники используют ее для эксфилтьтрации и С2

Как и ICMP туннели DNS аномалии начинаются после исполнения уязвимости. Злоумышленник создает доменный адрес и настраивает его как C2 канал. Вредоносное ПО или команды, выполняемые после эксплуатации, отправляют DNS запросы на сервер C2. Однако эти запросы длиннее стандартных DNS запросов и формируются для адресов поддоменов. Эти адреса не являются фактическими, это закодированные команды

```
encoded-commands.maliciousdomain.com
```

Когда этот запрос отправляется на сервер C2, сервер отправляет фактические фредоносные команды хосту. Поскольку DNS запросы являются естественной частью сетевой активности, эти пакеты могут оставаться незамеченными сетевыми параметрами. специалист по безопасности должен знать как исследовать длину DNS пакетов и целевые адреса чтобы обнаружить эти аномалии

| **Notes**                                                                                                                                                                                                                                                                                                                                                                                                                                                              | **Wireshark Filter**                                         |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Global search                                                                                                                                                                                                                                                                                                                                                                                                                                                          | `dns`                                                        |
| Для быстрого результата проверяйте:<br>- Длину запросов<br>- Аномальные и нерегулярные имена в DNS адресах<br>- Длинные DNS адреса с закодированным субдоменным адресом<br>- Известные паттерны такие как dnscat и dns2tcp<br>- Статистический Анализ, например аномально большого объема DNS запросов к определенному целевому объекту<br><br>!mdns - должно быть отключено, как правило поиска устройств в локальной сети, чтобы отчистить выдачу от локальных машин | `dns contains "dnscat"`<br>`dns.qry.name.len > 15 and !mdns` |

# Clear Text анализ протоколов
## FTP анализ 

> [!NOTE] FTP
> File Transfer Protocol разработан для легкой доставки файлов, поэтому он больше направлен на легкость чем на безопасность. Как результат этого, использование этого протокола в небезопасной среде создает следующие риски 
> - Атаки MITM
> - Credential stealing и unauthorised access
> - Phishing
> - Malware planting
> - Data Exfiltration

### User Agent анализ
Так как злоумышленники используют сложные методы для осуществления атак, они пытаются оставить следы которые похожи на обычный трафик, используя известные и проверенные протоколы. Для аналитика важно выявлять признаки аномалий в отдельных фрагментах пакетов. Поле `User-Agent` это один из лучших ресурсов для обнаружения аномалий в HTTP трафике. В некоторых случаях злоумышленники изменяют данные `User-agent`, что может выглядеть совершенно естественно. Аналитик не может полагаться только на поле `User-Agent` для обнаружения аномалий. Никогда не добавляйте `User-Agent` в белый список, даже если он выглядит естественно. Обнаружение, поиск аномалий на основе `User-Agent` это дополнительный источник данных, полезный при обнаружении очевидной аномалии. Если вы не уверены в каком либо значении, вы можете выполнить поиск в интернете чтобы проверить свои данные с помощью информации `User-Agent` по умолчанию
