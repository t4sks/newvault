# Процессы
Процесс представляет исполняемую программу, приложение может содержать один или несколько процессов. Процесс имеет множество компонентов разбитых на части для хранения и взаимодействия с ними. 
Каждому процессу предоставляются ресурсы для исполнения программы. У процесса есть виртуальное адресное пространство, исполняемый код, открытые дескрипторы системных объектов, контекст безопасности, уникальный идентификатор процесса, переменные среды, класс приоритета, минимальный и максимальный размеры рабочего набора и как минимум один поток выполнения

Процесс это ядро того как функционирует Windows. Процессы это ядро того как функционирует Windows, большая часть функциональности windows может быть реализована как приложение и иметь соответствующий процесс. Ниже приведены несколько примеров приложений по умолчанию запускающих процессы

- MsMpEng (Microsoft Defender)
- wininit (keyboard and mouse)
- lsass (credential storage)

Атакующие могут нацелиться на процессы для обхода детектирования и для того чтобы спрятать malware как легитимный процесс. Ниже приведен маленький перечень потенциальных векторов атак, которые злоумышленники могут использовать против процессов

- Process Injection
- Process Hollowing
- Process Masquerading

Процессы имеют много компонентов, их можно разбить на ключевые характеристики которые мы можем использовать для описания процессов на высоком уровне. В таблице ниже показаны критические части процессов и их назначение

| Компонент процесса            | Назначенин                                                                                               |
| ----------------------------- | -------------------------------------------------------------------------------------------------------- |
| Private Virtual Address Space | Адреса виртуальной памяти, выделяемые для данного процесса                                               |
| Исполняемая программа         | Определяет код и данные, хранящиеся в адресном пространстве                                              |
| Открытые дескрипторы          | Определяет дескрипторы системных ресурсов, доступные процессу                                            |
| Контекст безопасности         | Маркер доступа определяет пользователя, группы безопасности, привилегии и прочую информацию безопасности |
| Идентификатор процесса PID    | Уникальный числовой идентификатор процесса                                                               |
| Потоки                        | Фрагмент процесса, планируемый для выполнение                                                            |
Процесс можно также рассмотреть на более низком уровне - в том виде, в котором он располагается в виртуальном адресном пространстве. Таблица и диаграмма ниже отображают структура процесса в памяти

| Компонент             | Назначение                                         |

| Куча процессов        | Определяет кучу в которой хранятся данные          |
| Ресурсы процесса      | Определяет дополнительные ресурсы процесса         |
| Блок окружения        | Структура данных описывающая информацию о процессе |

# Threads
Поток это исполняемая единица используемая процессом и планируемая на основе параметров устройства

Параметры устройства могут варьироваться в зависимости от характеристик процессора и памяти, приоритета логических факторов а так же других факторов. 

Мы можем упростить определение потока: "Управление выполнением процесса"

Поскольку потоки управляют выполнением это часто используемый объект для атак. Злоупотребление потоками может использоваться само по себе для выполнения кода или же оно чаще используется в цепочках с другими вызовами API в рамках других методов

Потоки разделяют те же детали и ресурсы что и родительский процесс, такие как код, глобальные переменные и т.д. Потоки также имеют свои уникальные значения и данные описанные в таблице ниже

| Компонент                        | Назначение                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------- |
| Стек                             | Все данные, относящиеся к конкретному потоку(Исключения, вызовы процедур и так далее) |
| Локальное хранилище потока (TLS) | Указатели для выделения хранилища под уникальную среду данных                         |
| Аргумент Стека                   | Уникальное значение присваиваемое кажэдому потоку                                     |
| Структура контекста              | Хранит значения машинных регистров, поддерживаемые ядром                              |
# Virtual Memory
Виртуальная память - критически важный компонент того, как внутренние механизмы Windows функционируют и взаимодействуют друг с другом. Виртуальная память позволяет внутренним компонентам работать с памятью так, как если бы они была физической, устраняя иск коллизий между приложениями. 

Виртуальная память предоставляет каждому процессу собственное виртуальное адресное пространство. Менеджер памяти используется для трансляции виртуальных адресов в физические. Наличие приватного виртуального адресного пространства и отсутствие прямой записи в физическую память, снижает риск повреждения данных процессами

Менеджер памяти также использует страницы и перемещения для управления памятью. Приложения могут использовать больше виртуальной памяти, чем выделено физической. Менеджер памяти решает эту проблему путем вытеснения (свопинга) страниц виртуальной памяти на диск. Эту концепцию можно визуализировать на схеме ниже

Теоретический максимум виртуального адресного пространства на 32 битной системе х86 составляет 4гб

Это пространство разделено пополам: нижняя половина (0x00000000 - 0x7FFFFFFF) выделяется процессам как описано выше. Верхняя половина (0x80000000 - 0xFFFFFFFF) выделяется для нужд операционной системы. Администраторы могут изменить это распределение для приложений, требующих большего адресного пространства через параметр increaseUserVA или AWE(Address Windowing Extensions)

Теоретический максимум виртуального адресного пространства на современной 64-битной системе составляет 256тб. Соотношение разбивки адресного пространства из 32 битной системы сохраняется в 64 битной

Большинство проблем, требовавших настройки IncreaseUserVA или AWE решаются за счет увеличенного теоретического максимума
