# 06 - Фишинг

[[00 - SOC Junior Roadmap (BiZone)]]

## Почтовые протоколы и инфраструктура (прямо в вакансии)

- [ ] **SMTP** (отправка, порт 25/587/465) — как идёт письмо, MTA/MUA, конверт vs заголовки
- [ ] **POP3** (получение, порт 110/995) — забирает и обычно удаляет с сервера
- [ ] **IMAP** (получение, порт 143/993) — синхронизация, письма остаются на сервере
- [ ] Заголовки письма: Received (цепочка), From, Return-Path, Reply-To, Message-ID
- [ ] **Spoofing** — подмена отправителя, почему SMTP это позволяет
- [ ] SPF, DKIM, DMARC — как защищают от спуфинга

## Что такое фишинг

- [ ] Определение: социнженерия для кражи данных / доставки ВПО
- [ ] Виды: массовый фишинг, spear phishing (целевой), whaling, smishing (SMS), vishing (звонок)
- [ ] BEC (Business Email Compromise)

## Векторы заражения

- [ ] **Почта** — поддельный отправитель, спуфинг домена, похожие домены (typosquatting)
- [ ] **Ссылка** — фишинговая страница (поддельный логин), редиректы, сокращатели URL
- [ ] **Документ docx/xlsx** — вредоносные макросы (VBA), Follina, template injection, DDE
- [ ] **Страница** — credential harvesting, clone-сайты, OAuth-фишинг
- [ ] PDF с эксплойтами/ссылками
- [ ] Вложения-архивы (пароль в письме для обхода AV), ISO/LNK/HTA

## Как разбирать фишинг (SOC-задача)

- [ ] Анализ заголовков письма (Received, SPF, DKIM, DMARC)
- [ ] Проверка отправителя vs Reply-To vs Return-Path
- [ ] Извлечение и проверка URL (без перехода — sandbox/urlscan)
- [ ] Анализ вложений в песочнице
- [ ] Проверка макросов в docx (oletools: olevba)
- [ ] Поиск кто ещё получил письмо (рассылка), кто перешёл/открыл

## Детект и защита

- [ ] SPF / DKIM / DMARC — как работают, что проверяют
- [ ] Sandbox detonation вложений
- [ ] URL-rewriting / time-of-click protection
- [ ] Корреляция: переход по ссылке → загрузка → запуск процесса

## 🧪 Тест для повторения

> [!question]- 1. SMTP, POP3, IMAP — назначение и порты.
> SMTP — отправка/пересылка почты (25 между серверами, 587/465 submission). POP3 — получение, скачивает и обычно удаляет с сервера (110/995). IMAP — получение с синхронизацией, письма остаются на сервере (143/993). Зашифрованные варианты — 995/993/465.

> [!question]- 2. Почему возможен email spoofing и что с этим делают SPF/DKIM/DMARC?
> SMTP исторически не проверяет подлинность отправителя — поле From задаётся произвольно. SPF проверяет, имеет ли право IP отправлять от имени домена. DKIM — криптоподпись письма. DMARC — политика, что делать при провале SPF/DKIM + отчётность.

> [!question]- 3. Какие заголовки письма проверять при разборе фишинга?
> Received (цепочка серверов — путь письма), From vs Return-Path vs Reply-To (несоответствие = подозрительно), Message-ID, результаты Authentication-Results (SPF/DKIM/DMARC), домен отправителя на typosquatting.

> [!question]- 4. Векторы доставки в фишинге (минимум 4).
> Почтовая ссылка на фейк-логин (credential harvesting), вредоносное вложение docx/xlsx с макросами (VBA), архив с паролем (обход AV), LNK/HTA/ISO, PDF со ссылкой/эксплойтом, OAuth-фишинг.

> [!question]- 5. Как безопасно разобрать вредоносный docx?
> Не открывать на рабочей машине. Статически: olevba (oletools) — извлечь и проверить VBA-макросы, авто-исполняемые (AutoOpen/Document_Open), обфускацию, URL. Детонация в песочнице. Проверить вложение/URL на VirusTotal/urlscan.

> [!question]- 6. Корреляция: как связать фишинг с последующей компрометацией?
> Письмо получено → переход по ссылке (прокси-лог) → загрузка файла → запуск процесса (Sysmon EID 1) → сетевое соединение к C2 (EID 3). Найти всех получателей рассылки, кто открыл/перешёл, изолировать.
