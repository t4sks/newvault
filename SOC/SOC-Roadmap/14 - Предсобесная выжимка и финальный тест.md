# 14 - Предсобесная выжимка и финальный тест

[[00 - SOC Junior Roadmap (BiZone)]]

> **Зачем.** За 3-5 дней до собеседования. Две части: (А) **Выжимка** — плотный конспект всего, что спросят, для быстрого повторения; (Б) **Финальный тест** — симуляция живого собеседования вслух. За день до собеса прочитай выжимку утром и вечером, тест прогони с таймером.

---

# ЧАСТЬ А. ВЫЖИМКА (читать целиком за один присест)

## Linux — must know
- Потоки: 0 stdin, 1 stdout, 2 stderr. `2>&1` = stderr туда же, куда stdout. Порядок важен.
- Логи: `auth.log`/`secure` (аутентификация), `last`/wtmp (успешные), `lastb`/btmp (неудачные), journalctl (systemd), `.bash_history`.
- Persistence: cron, systemd timer, authorized_keys, .bashrc, ld.so.preload, PAM, kernel module, udev, rc.local. Детект — изменение/появление этих файлов + auditd.
- Privesc: SUID (`find / -perm -4000`), sudo-misconfig, ядро. GTFOBins.
- auditd — аудит ядра по правилам (-w файл -p wa -k метка). SELinux/AppArmor — MAC поверх DAC, ограничивает даже root.

## Windows — must know
- Реестр: SAM (хеши локальных), SECURITY (LSA-секреты), SOFTWARE, SYSTEM (службы+bootkey). HKCU=NTUSER.DAT. Автозапуск — Run/RunOnce.
- Креды: дамп LSASS (mimikatz/procdump/comsvcs), SAM+SYSTEM offline, DCSync. Детект LSASS — Sysmon EID 10.
- EventID: 4624 вход / 4625 неуспех / 4672 админ / 4688 процесс / 4698 задача / 4720 учётка / 4768-4769 Kerberos / 7045 служба / 4662 AD-объект (DCSync).
- Logon Type: 2 интерактив, 3 сеть, 10 RDP, 9 NewCredentials.
- Sysmon EID: 1 процесс, 3 сеть, 7 imageload, 8 remotethread, 10 process access, 11 file, 13 registry.
- Процессы: System(4)→smss→csrss/wininit→services→svchost; winlogon→userinit→explorer. Аномалии: lsass→cmd, svchost не от services, winword→powershell.
- AMSI сканирует скрипты; обфускация base64/Deflate; детект PowerShell — Event 4104.

## Сети — must know
- NAT: SNAT (источник), DNAT (назначение), PAT (порты). Ломает атрибуцию.
- TCP: SYN→SYN-ACK→ACK; RST сброс. OSI 7 уровней + протоколы.
- Атаки: L2 ARP spoof/MAC flood, L3 IP spoof, L4 SYN flood, L7 SQLi/DNS spoof.
- MITM (ARP/DNS spoof) — детект дубли MAC↔IP. DNS-туннель — длинные поддомены/TXT.
- DMZ — буфер для публичных сервисов, сегментация против латерального движения.
- Туннели: SSH -L/-R/-D, DNS, ICMP, GRE, IPsec.

## Active Directory — must know
- Kerberos: AS-REQ→TGT(krbtgt)→TGS-REQ→ST→AP-REQ. NTLM — challenge-response (отсюда PtH).
- Атаки: Kerberoasting (4769 RC4), AS-REP roast (4768 no-preauth), DCSync (4662), Golden (krbtgt TGT)/Silver (сервис ST), PtH/PtT, NTLM Relay.
- NTDS.dit на DC = все хеши. krbtgt = ключ ко всему. SPN = мишень Kerberoasting.
- BloodHound — граф путей к DA, детект по массовым LDAP.

## MITRE / Kill Chain — must know
- Kill Chain: Recon→Weaponize→Deliver→Exploit→Install→C2→Actions.
- ATT&CK: Tactic (зачем) / Technique Txxxx (как) / Procedure (реализация). 14 тактик Enterprise.
- Связки: T1003 cred dump, T1059.001 PowerShell, T1053 scheduled task, T1021 remote services.

## Web / OWASP — must know
- 2017 (конкретнее): Injection, Broken Auth, XXE, Broken Access Control (IDOR), XSS, Deserialization.
- 2021: A01 Broken Access Control, A03 Injection, A10 SSRF.
- SQLi (error/union/blind), XSS (reflected/stored/DOM), IDOR, SSRF (cloud metadata), CSRF.
- Детект: access.log — аномальные URL/UA, ' UNION, признаки сканеров, web shell.

## Фишинг / ВПО — must know
- SMTP 25/587, POP3 110, IMAP 143. Spoofing возможен (SMTP не проверяет From). SPF (IP)/DKIM (подпись)/DMARC (политика+выравнивание).
- Разбор: Received, From vs Return-Path vs Reply-To, olevba для docx, urlscan/VT для URL/вложений.
- ВПО: вирус/червь/троян/RAT/ransomware/wiper/rootkit/fileless. Dropper→loader→stager. IOC: хеши/IP/домены/мьютексы. Вердикт: Тип.Платформа.Семейство.

## C2 / DFIR / SIEM — must know
- C2: beacon/listener/callback/jitter. Каналы HTTP(S)/DNS/SMB/ICMP. Детект beaconing — регулярность, JA3/JA4, UA.
- Pivoting: SSH-туннели, chisel, ligolo, proxychains. Детект — внутренние соединения, цепочки логонов.
- DFIR PICERL: Prep/Identify/Contain/Eradicate/Recover/Lessons. Volatility для памяти. Forensics: Prefetch/Amcache/ShimCache/MFT.
- SIEM (корреляция) / EDR (эндпоинт) / NTA (трафик). Цикл инцидента L1: регистрация→анализ→эскалация→закрытие. FP-тюнинг, исключающая логика. Sigma/YARA/Suricata.

# ЧАСТЬ Б. ФИНАЛЬНЫЙ ТЕСТ (симуляция собеседования)

> **Правила.** Отвечай ВСЛУХ, как на реальном собесе — связно, 30-60 сек на ответ. Запиши себя на диктофон или проси меня провести устно. Спойлер открывай только после своего ответа.

## Раунд 1 — «Расскажи про себя как про SOC» (открытые вопросы)

- [ ] 1. Объясни своими словами, чем занимается SOC-аналитик L1.
> [!question]- ориентир
> Мониторинг алертов SIEM, триаж (TP/FP), сбор контекста инцидента, первичные рекомендации, эскалация на L2, работа в тикет-системе по SLA.

- [ ] 2. Что такое модель «атака → артефакт → детект» и почему это суть работы?
> [!question]- ориентир
> На каждую технику атаки знать, какой артефакт/лог её выдаёт. SOC мыслит от детекта. Пример: LSASS dump → Sysmon EID 10.

- [ ] 3. Проведи меня по Kill Chain на примере фишинговой атаки.
> [!question]- ориентир
> Recon (сбор адресов) → Weaponize (docx с макросом) → Deliver (письмо) → Exploit (макрос) → Install (persistence) → C2 (beacon) → Actions (эксфильтрация). На каждом — точка детекта.

## Раунд 2 — Блиц (быстрые, по 15-20 сек)

- [ ] 4. Где в Windows хранятся хеши паролей? → [[04 - Windows]]
> [!question]- ответ
> Локальные — SAM (+SYSTEM для bootkey), в памяти — LSASS, доменные — NTDS.dit на DC.

- [ ] 5. Какой EventID = успешный вход? Неудачный?
> [!question]- ответ
> 4624 успешный, 4625 неудачный.

- [ ] 6. Как найти SUID-бинари в Linux?
> [!question]- ответ
> `find / -perm -4000 -type f 2>/dev/null`.

- [ ] 7. Что такое Kerberoasting в одном предложении?
> [!question]- ответ
> Запрос service ticket для аккаунта с SPN и offline-брут его хеша; детект — 4769 с RC4.

- [ ] 8. Чем SIEM отличается от EDR?
> [!question]- ответ
> SIEM коррелирует логи отовсюду; EDR детектит поведение на эндпоинте.

- [ ] 9. SNAT vs DNAT?
> [!question]- ответ
> SNAT меняет источник (выход наружу), DNAT — назначение (проброс внутрь).

- [ ] 10. Три типа XSS?
> [!question]- ответ
> Reflected, Stored, DOM-based.

- [ ] 11. Что такое beaconing?
> [!question]- ответ
> Регулярные callback импланта к C2; детект по периодичности.

- [ ] 12. SMTP-порт и почему spoofing возможен?
> [!question]- ответ
> 25/587; SMTP не проверяет подлинность поля From.

- [ ] 13. Что показывает Autoruns?
> [!question]- ответ
> Все точки автозапуска Windows (Run-ключи, задачи, службы, DLL) — поиск persistence.

## Раунд 3 — Сценарии (главное! здесь проверяют мышление)

- [ ] 14. **Алерт:** powershell.exe запущен с `-enc <длинная base64>`, родитель — winword.exe. Твои действия?
> [!question]- ориентир
> Сильное подозрение на фишинг с макросом. Декодировать base64 (что за команда), проверить родителя (winword→powershell = аномалия), сетевые соединения (Sysmon EID 3), скачивалась ли нагрузка, кто юзер/хост, искать рассылку письма. Вероятно TP → эскалация + изоляция.

- [ ] 15. **Алерт:** на контроллере домена Event 4662 с правом репликации от рабочей станции бухгалтера. Что это?
> [!question]- ориентир
> DCSync — выгрузка хешей через имитацию репликации. Рабочая станция не должна реплицировать! Высокий приоритет, вероятный захват домена. Containment: изолировать хост/учётку, искать как получили права, сброс krbtgt при подтверждении.

- [ ] 16. **Алерт:** множество 4625 (неудачные входы) с одного IP, потом один 4624 (успех). Что произошло и что делать?
> [!question]- ориентир
> Брутфорс, увенчавшийся успехом. Проверить Logon Type, учётку, источник, что делал после входа. Containment: блок IP, сброс пароля учётки, проверка persistence и латерального движения.

- [ ] 17. **На Linux-сервере** в /tmp появился исполняемый файл, который держит исходящее соединение на нестандартный порт. Разбор?
> [!question]- ориентир
> Вероятный имплант/C2. `ls -la /proc/<pid>/exe` (что за бинарь, даже если удалён), `ss -tnp` (куда соединение), хеш файла на VT, проверка persistence (cron/systemd/authorized_keys), auth.log (как попал). Изоляция, сбор IOC.

- [ ] 18. **Заказчик прислал** подозрительное письмо с вложением invoice.docx. Твой плейбук?
> [!question]- ориентир
> Не открывать на рабочей. Заголовки (Received, From vs Return-Path, SPF/DKIM/DMARC), olevba по docx (макросы AutoOpen, URL), URL/хеш на urlscan/VT, кто ещё получил, кто открыл. Вердикт TP/FP, при TP — блок отправителя, поиск сработавших.

- [ ] 19. **Как отличишь** ложное срабатывание от реальной угрозы на примере «PowerShell скачал файл»?
> [!question]- ориентир
> Контекст: кто запустил (админ в рабочее время vs юзер ночью), что за URL (внутренний репозиторий vs неизвестный домен), родитель процесса, репутация, baseline (бывает ли это в норме). FP — легитимный скрипт автоматизации; TP — неизвестный источник + подозрительная цепочка.

- [ ] 20. **Объясни**, что ты сделаешь от момента получения алерта до закрытия тикета.
> [!question]- ориентир
> Принять алерт → понять, что сработало → собрать контекст (хост/юзер/процесс/сеть) → сверить с baseline и IOC → классифицировать TP/FP → дать рекомендации/уведомить заказчика → при TP эскалировать на L2 с собранными данными → задокументировать и закрыть, при FP — предложить тюнинг правила.
