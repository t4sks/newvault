1 Какие исполняемые файлы существуют в windows

- **.exe** — обычный исполняемый файл
- **.dll** — подключаемая динамическая библиотека
- **.sys** — драйвера устройств

---
2 Из чего состоит исполняемый файл в Windows

1. **Заголовки**. Инструкции по запуску и исполнению программы.
2. **Секции**. Блоки данных с различным содержимым произвольного размера.
3. **Остальные данные**. Сюда записывается информация, которая может быть необходима коду программы для работы.    

---
3 Режимы возможного состояния процесса
- **Start** — начальное состояние при создании процесса.
- **Ready** — режим готовности, процесс ожидает исполнения на процессоре. В течение работы процессор может переключаться между процессами, переводя одни в режим готовности, другие – в режим исполнения.
- **Running** — выполнение инструкций.
- **Wait** — процесс переходит в состояние ожидания. Например, ждёт ввода данных или получения доступа к файлу.
- **Terminated** — как только процесс будет завершён, он перейдёт в это состояние и будет ожидать удаления.

---
4 Какие системные процессы вы знаете

- Idle (PID 0) - Содержит один поток для каждого процессора и используется для учёта времени бездействия процессора
- **System**. (PID 4) Содержит большинство системных потоков и дескрипторов режима ядра
- **Диспетчер сеансов (Smss.exe)**. Отвечает за инициализацию переменных окружения и запуск **csrss.exe** и **winlogon.exe**. Также может запускать программы, работающие до загрузки основной ОС. Например, **chkdsk**. Запускает csrss.exe (Подсистема Windows) и wininit.exe в сессии 0 изолированной сессии Windows для операционной системы и csrrss.exe и winlogon.exe для сессии 1, которая является пользовательской сессией. Первый дочерний экземпляр создает дочерние экземпляры в новых сессиях, что осуществляется путем копирования smss.exe самого себя в новую сессию и самозавершения.
- **Подсистема клиент/сервер времени выполнения (Csrss.exe)**. Отвечает за работу приложений с интерфейсом командной строки и создание потоков в ОС. Также она участвует в работе служб удалённого доступа к рабочему столу.
- **Инициализация сеанса 0 (Wininit.exe)**. Отвечает за запуск основных фоновых процессов, в частности **services.exe**, **lsass.exe**, **lsaiso.exe**.
- **Процесс входа (Winlogon.exe)**. Обрабатывает интерактивный вход и выход пользователей из системы.
- **Диспетчер служб (Services.exe)** и создаваемые им дочерние процессы, такие как системный обобщённый процесс, который выполняет функции хоста служб (Svchost.exe).
- **Локальная служба аутентификации (Lsass.exe)** и, если активен механизм Credential Guard, **изолированный локальный сервер аутентификации (Lsaiso.exe)**.
- **Проводник Windows (explorer.exe)**. Процесс, который предоставляет функции рабочего стола, пользовательский интерфейс и реализует работу с файлами и приложениями через графический интерфейс.

5 Примеры системных служб

- **DNS-клиент (dnscache)** — это служба, которая кэширует имена DNS (Domain Name System) и регистрирует полное имя данного компьютера.
- **Журнал событий** — это служба, которая собирает события, полученные от ОС и сторонних приложений. Именно она формирует журналы аудита Windows, с которыми и работают аналитики SOC.

6 Принцип Process Injection

Это метод выполнения произвольного кода в адресном пространстве действующего процесса
Выполнение замаскировано под легитимный процесс, поэтому пользователи и средства защиты не всегда могут определить наличие вредоноса

---
7 Принцип DLL Injection

Здесь перед внедрением вредоносной программе нужна копия вредоносной DLL библиотеки, уже сохраненной в системе жертвы. Атакующие создают новый поток в одном из активных приложений и добавляют в него свою вредоносную DLL

---
8 Дискреционный контроль в windows

При дискреционном доступе определенные операции над конкретным ресурсом запрещаются или разрешаются субъектам.
В Windows реализовано с помощью матрицы доступа DACL - Discretionary Access Controll List
Ее можно увидеть через свойства объекта во вкладке безопасность

---
9 RBAC

Реализация представляет собой набор прав доступа к объектам информационной системы, которые определяют какой набор действий может быть выполнен по отношению к ним. Этот набор должен соответствовать выполняемой работником трудовой функции

Применяется в комбинации из DACL и RBAC, пользователей заводят через групповые политики Windows (GPO) в систему, назначают привилегии, которые соответствуют функциям сотрудника, а затем точечно назначают дополнительные доступы с помощью DACL

10 SID 

Структура которая идентифицирует учетную запись пользователя

Принцип организации управляемого доступа выглядит следующим образом: у каждого есть свой маркер доступа, в котором указан уникальный идентификатор пользователя SID. Он состоит из нескольких частей

SID S-1-5-21-1507001333-1204550764-1011284298-1003
Формат идентификатора безопасности такой: S-R-IA-SA-SA-RID

- R - первое число, которое называется номером редакции, оно всегда равно 1
- IA - источник выдачи (issuing authority)
- SA - уполномоченный центр(sub-authority) определяет специальные группы и функции
Например число 21 указывает что идентификатор был выдан контроллером домена или изолированным компьютером.
- Три длинные последовательности цифр 1507001333-1204550764-1011284298 определяют конкретную машину которая выдала идентификатор. Числа генерируются случайно при установке ОС
- RID - относительный идентификатор(Relative Identifier). Уникальное порядковое число присвоенное учетной записи(пользователя, компьютера или группы) уполномоченным SA. Относительные идентификаторы RID для встроенных учетных пользователей (Администратор и Гость) одинаковы для всех компьютеров

RID для встроенной учетной записи ADministrator имеет значение 500, а для учетной записи Гость 501

Процессы которые создает пользователь, наследуют его маркер и содержат информацию о том с какими привилегиями они исполняются и от чьего имени. Можно сказать что процессы содержат маркер доступа

С другой стороны все объекты в системе содержат структуру данных, которая называется дескриптором защиты(Security Descriptor, SD). В это структуру входит список SID пользователей которые могут или не могут получить доступ к объекту.

Дескриптор защиты включает в себя следующие поля

- Owner - владелец SID
- DACL(Дискреционный ACL) - определяет какие пользователи могут выполнять определенные операции с объектом
- SACL(Системный ACL) - системный список управления доступом. В нем перечислены пользователи и операции, которые должны учитываться в журнале аудита безопасности

Когда процесс пытается получить доступ к объекту, его идентификатор сравнивается с идентификатором в системе защиты объекта.
