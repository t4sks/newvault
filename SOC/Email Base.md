# Почтовые протоколы
Когда вы отсылаете сообщение разные протоколы работают вместе, сценарии передачи сообщения от отправителя к получателю и каждый протокол играет свою специфическую роль

- Simple Mail Transfer Protocol (SMTP) - отправляет письма
- Post Office Protocol (POP3) - загружает электронные письма на устройства
- Internet Message Access Protocol (IMAP) - синхронизирует электронную почту между устройствами

При получении электронных писем ваш почтовый сервис будет использовать либо POP3 либо IMAP в зависимости от настроек вашего почтового ящика. Рассмотрим оба протокола ниже:

## POP3
- Сообщения загружаются и хранятся на одном устройстве
- Отправленные сообщения хранятся на том же устройстве с которого было отправлено электронное письмо
- Доступ к электронным письмам возможен только с того устройства на которое они были отправлены
- После загрузки электронные письма обычно удаляются с сервера
## IMAP
- емайлы хранятся на сервере и могут быть загружены на множество девайсов
- Отправленные сообщения хранятся на сервере
- Синхронизация сообщений между различными устройствами 
- Электронные письма остаются на сервере если их явно не удалить

# Путь прохождения письма:
1. Пользователь отправляет email: почтовый клиент отправителя отправляет сообщение на его почтовый сервер используя SMTP
2. Почтовый сервер спрашивает DNS: отправляющий сервер запрашивает у DNS почтовый сервер домена получателя
3. DNS отвечает: DNS возвращает адрес почтового сервера получателя
4. Письмо доставлено: сообщение отправляется через интернет на сервер получателя
5. Получатель проверяет почтовый ящик: почтовый клиент подключается к почтовому серверу напрямую
6. Электронное письмо получено: сообщение загружается (POP3) или синхронизируется (IMAP) на устройстве получателя

# Способы защиты от фишинга 
## SPF Sender policy Framework
Dmarican - платформа предназначенная для защиты почтовых отправлений от фишинга, определяет структуру политики отправителя(SPF)
Структура политики отправителя SPF используется для аутентификации отправителя электронного письма. При наличии SPF интернет провайдеры могут проверить, что почтовый сервер имеет право отправлять электронные письма для определенного домена. Запись SPF это DNS TXT-запись которая содержит список IP адресов, которым разрешено отправлять электронные письма от вашего домена![[Pasted image 20260601154047.png]]
Таким образом при отправке электронного письма принимающий почтовый сервер проверяет запись SPF домена, чтобы убедится, что отправляющий сервер имеет право отправлять сообщения от имени этого домена. Доставка электронного письма зависит от результата проверки записи SPF

| Результат верификации |                      планируемое действие                       |
| :-------------------: | :-------------------------------------------------------------: |
|  Pass, Neutral, None  | **Accept**; Принять(разрешить и обработать электронное письмо)  |
|  SoftFail, PermError  | **Flag**; Ставит флаг(Помечает как подозрительное но разрешает) |
|    Fail, TempError    |        **Reject**; Отклонить(немедленно удалить письмо)         |
## Записи SPF 
Пример записи SPF
```
v=spf1 ip4:127.0.0.1 include:_spf.google.com -all
```
- `v=spf1` - флаг начала SPF записи
- `ip4:127.0.0.1` - указывает на то какой IP может отправлять почту
- `include:_spf.google.com` - указывает на то какой домен может отправлять почту
- `-all` - неавторизованные email должны быть оклонены

## DomainKeys Indentified Mail (DKIM) 

> [!note] определение
> Расшифровывается как: Идентифицированная почта с помощью domainkey. Используется для аутентификации отправляемого электронного письма. Как и SPF, DKIM это открытый стандарт аутентификации электронной почты, который используется для согласования с DMARC. Запись DKIM существует в DNS, но она сложнее чем SPF. Преимущество DFIM заключается в том, что она может сохраняться при переадресации, что делает ее превосходящей SPF и основной для защиты электронной почты

![[Pasted image 20260601160633.png]]

Когда письмо отправляется, то отправляющий сервер использует закрытый ключ для добавления цифровой подписи к этому письму. Принимающий сервер получает открытый ключ из записи DKIM домена, чтобы проверить действительно ли сообщение отправлено с этого домена. Если подпись совпадает, письмо подлинное, в противном случае оно может быть помечено как подозрительное или отклонено
### DKIM Records
Вот так выглядит запись для DKIM 
```
v=DKIM1; k=rsa; p=<public_key>
```
- `v=DKIM1;` - указывает на используемую версию DKIM
- `k=rsa;` - указывает на тип ключа, обычно RSA это стандарт
- `p=` - это публичный ключ который будет сопоставляться с приватным чтобы верифицировать сигнатуру DKIM

> [!warning] ВАЖНО!!!!
> записи DKIM могут отличаться в зависимости от версии и реализации

## Domian Based Message Authentication, Reporting and Conformance (DMARC)

> [!note] DMARC
> Использует концепцию которую называют выравниванием, чтобы связать результаты двух других стандартов с открытым исходным кодом, SPF и DKIM. DMARC проверят что домен отправителя совпадает с доменами, которые проверили SPF и DKIM
> Если совпадения нет, то DMARC говорит серверу получателя, что делать с письмом: пропустить, отправить в спам или отклонить. Это поведение задается политикой в DNS записи `none\quarantine\reject`

По факту гарантирует чтобы в поле `FROM` был одинаковый адрес между видимым значением и SPF/DKIM
### DMARC запись
```
v=DMARC1; p=quarantine; rua=mailto:postmaster@website.com
```
- `v=DMARC1;` - версия DMARC(обязательна)
- `p=quarantine` - политика DMARC(quarantine = поместить в спам)
- `rua=mailto:postmaster@website.com` - необязательный тег, указывает адрес на который почтовые серверы будут слать агрегированные отчеты о письмах прошедших через DMARC

## Secure/Multipurpose Internet Mail Extensions (S/MIME)

> [!note] Secure/Multipurpose Internet Mail Extensions (S/MIME)
> S/MIME - Это стандартный протокол для отправки подписанных и зашифрованных сообщений, который основан на ассиметричной криптографии (публичный ключ открыт а приватный не передается никогда)

### Два основных компонента и функции безопасности S/MIME
#### **Digital Signature** - цифровая подпись
Отправляющий подписывает сообщение вместе с его приватным ключом, получатель проверяет отправителя с использованием публичного ключа. Это обеспечивает:
- Аутентификацию - подтверждает личность от
- Неотрицаемость - отправитель не может отрицать факт отправки письма
- Целостность - любое изменение письма после отправки будет обнаружено
#### **Encryption** - шифрование
Отправитель шифрует сообщение с использованием публичного ключа получателя, расшифровать может только получатель своим приватным ключом, это решает проблему:
- Конфиденциальности - содержимое недоступно никому кроме адресата
### Пример S/MIME 
- Боб хочет безопасно отправить email с S/MIME для Mary
- Боб создает цифровой сертификат для цифровой подписи (**Digital Signature**)
- Боб подписывает письмо своим приватным ключом (**Digital Signature**)
- Боб открыто передает свой публичный ключ Mary (**Digital Signature**)
- Боб так же просит Mary публичный ключ для зашифрования email (Encryption)

- Mary проверяет подпись публичным ключом боба
- Mary расшифровывает письмо своим приватным ключом
- Для ответа Mary повторяет ту же процедуру что и Боб
- После обмена сертификатами оба хранят их для переписки
