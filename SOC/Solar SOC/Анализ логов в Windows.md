Журналы аудита операционных систем - это записи о различных действиях выполняемых в ОС. Например, выход в систему, запуск приложений, изменение файлов и т.д.

# Основные журналы в ОС Windows

- Security (Безопасность) 
Что хранит:
	События влияющие на безопасность системы. Является основным журналом, который использует в работе SOC аналитик
Примеры событий:
	- удачные и неудачные попытки входа
	- запуски процессов
	- Попытка доступа к файлам
	- Работа с реестром
	- Действия с учетными записями

- System(Система)
Что хранит:
	События операционной системы или ее компонентов
Примеры событий:
	- Отказы драйверов
	- Проблемы при запуске событий

- Application(приложение)
Что хранит:
	Обычно это подробная информация о важных аварийных ситуациях в работе приложений. 
	Однако для каждого приложения разработчики сами определяют, какие события будут протоколироваться в журнале
Примеры событий:
	- Ошибки серверов баз данных
	- Проблемы возникающие при работе приложений

- Setup(установка)
Что хранит:
	События которые возникают при установке и настройке операционной системы и ее компонентов
Пример событий:
	Действия которые выполняются во время установки ОС и компонентов.
	Статистика производительности различных компонентов установки

- Forwarded Events (перенаправленные события)
Что хранит:
	Если настроена пересылка событий с одного компьютера на другой, то в этот журнал попадают события, пересылаемые с других серверов или хостов
Примеры событий:
	Любые события полученные от других хостов в сети

## EventID 4672 привилегии входа

Генерируется одновременно с успешной аутентификацией при предоставлении пользователю привилегий при входе 

![[Pasted image 20260627180758.png]]

Таким образом пользователь получил полномочия которые потенциально позволяют обойти некоторые средства управления безопасностью windows

Например пользователь с таким уровнем прав доступа может загружать драйвера, игнорировать ACL файлов при получении доступа на чтение, а также получает другие права которые могут нарушить политики ИБ

## EventID 4634 Выход из системы

Генерируется после завершения пользовательского сеанса. Это событие показывает, что сеанс входа в систему был завершен и больше не существует

![[Pasted image 20260627181121.png]]

Любые события, зарегистрированные после входа, будут сообщать тот же идентификатор входа в систему до события выхода из системы
