1 Какие исполняемые файлы существуют в windows

- **.exe** — обычный исполняемый файл
- **.dll** — подключаемая динамическая библиотека
- **.sys** — драйвера устройств

---
2 Из чего состоит исполняемый файл в Windows

1. **Заголовки**. Инструкции по запуску и исполнению программы.
2. **Секции**. Блоки данных с различным содержимым произвольного размера.
3. **Остальные данные**. Сюда записывается информация, которая может быть необходима коду программы для работы.    

---
3 Режимы возможного состояния процесса
- **Start** — начальное состояние при создании процесса.
- **Ready** — режим готовности, процесс ожидает исполнения на процессоре. В течение работы процессор может переключаться между процессами, переводя одни в режим готовности, другие – в режим исполнения.
- **Running** — выполнение инструкций.
- **Wait** — процесс переходит в состояние ожидания. Например, ждёт ввода данных или получения доступа к файлу.
- **Terminated** — как только процесс будет завершён, он перейдёт в это состояние и будет ожидать удаления.

---
4 Какие системные процессы вы знаете

- Idle (PID 0) - Содержит один поток для каждого процессора и используется для учёта времени бездействия процессора
- **System**. (PID 4) Содержит большинство системных потоков и дескрипторов режима ядра
- **Диспетчер сеансов (Smss.exe)**. Отвечает за инициализацию переменных окружения и запуск **csrss.exe** и **winlogon.exe**. Также может запускать программы, работающие до загрузки основной ОС. Например, **chkdsk**. Запускает csrss.exe (Подсистема Windows) и wininit.exe в сессии 0 изолированной сессии Windows для операционной системы и csrrss.exe и winlogon.exe для сессии 1, которая является пользовательской сессией. Первый дочерний экземпляр создает дочерние экземпляры в новых сессиях, что осуществляется путем копирования smss.exe самого себя в новую сессию и самозавершения.
- **Подсистема клиент/сервер времени выполнения (Csrss.exe)**. Отвечает за работу приложений с интерфейсом командной строки и создание потоков в ОС. Также она участвует в работе служб удалённого доступа к рабочему столу.
- **Инициализация сеанса 0 (Wininit.exe)**. Отвечает за запуск основных фоновых процессов, в частности **services.exe**, **lsass.exe**, **lsaiso.exe**.
- **Процесс входа (Winlogon.exe)**. Обрабатывает интерактивный вход и выход пользователей из системы.
- **Диспетчер служб (Services.exe)** и создаваемые им дочерние процессы, такие как системный обобщённый процесс, который выполняет функции хоста служб (Svchost.exe).
- **Локальная служба аутентификации (Lsass.exe)** и, если активен механизм Credential Guard, **изолированный локальный сервер аутентификации (Lsaiso.exe)**.
- **Проводник Windows (explorer.exe)**. Процесс, который предоставляет функции рабочего стола, пользовательский интерфейс и реализует работу с файлами и приложениями через графический интерфейс.

5 Примеры системных служб

- **DNS-клиент (dnscache)** — это служба, которая кэширует имена DNS (Domain Name System) и регистрирует полное имя данного компьютера.
- **Журнал событий** — это служба, которая собирает события, полученные от ОС и сторонних приложений. Именно она формирует журналы аудита Windows, с которыми и работают аналитики SOC.

6 Принцип Process Injection

Это метод выполнения произвольного кода в адресном пространстве действующего процесса
Выполнение замаскировано под легитимный процесс, поэтому пользователи и средства защиты не всегда могут определить наличие вредоноса

---
7 Принцип DLL Injection

Здесь перед внедрением вредоносной программе нужна копия вредоносной DLL библиотеки, уже сохраненной в системе жертвы. Атакующие создают новый поток в одном из активных приложений и добавляют в него свою вредоносную DLL

---
8 Дискреционный контроль в windows

При дискреционном доступе определенные операции над конкретным ресурсом запрещаются или разрешаются субъектам.
В Windows реализовано с помощью матрицы доступа DACL - Discretionary Access Controll List
Ее можно увидеть через свойства объекта во вкладке безопасность

---
9 RBAC

Реализация представляет собой набор прав доступа к объектам информационной системы, которые определяют какой набор действий может быть выполнен по отношению к ним. Этот набор должен соответствовать выполняемой работником трудовой функции

Применяется в комбинации из DACL и RBAC, пользователей заводят через групповые политики Windows (GPO) в систему, назначают привилегии, которые соответствуют функциям сотрудника, а затем точечно назначают дополнительные доступы с помощью DACL

10 SID 

Структура которая идентифицирует учетную запись пользователя

Принцип организации управляемого доступа выглядит следующим образом: у каждого есть свой маркер доступа, в котором указан уникальный идентификатор пользователя SID. Он состоит из нескольких частей

SID S-1-5-21-1507001333-1204550764-1011284298-1003
Формат идентификатора безопасности такой: S-R-IA-SA-SA-RID

- R - первое число, которое называется номером редакции, оно всегда равно 1
- IA - источник выдачи (issuing authority)
- SA - уполномоченный центр(sub-authority) определяет специальные группы и функции
Например число 21 указывает что идентификатор был выдан контроллером домена или изолированным компьютером.
- Три длинные последовательности цифр 1507001333-1204550764-1011284298 определяют конкретную машину которая выдала идентификатор. Числа генерируются случайно при установке ОС
- RID - относительный идентификатор(Relative Identifier). Уникальное порядковое число присвоенное учетной записи(пользователя, компьютера или группы) уполномоченным SA. Относительные идентификаторы RID для встроенных учетных пользователей (Администратор и Гость) одинаковы для всех компьютеров

RID для встроенной учетной записи ADministrator имеет значение 500, а для учетной записи Гость 501

Процессы которые создает пользователь, наследуют его маркер и содержат информацию о том с какими привилегиями они исполняются и от чьего имени. Можно сказать что процессы содержат маркер доступа

С другой стороны все объекты в системе содержат структуру данных, которая называется дескриптором защиты(Security Descriptor, SD). В это структуру входит список SID пользователей которые могут или не могут получить доступ к объекту.

Дескриптор защиты включает в себя следующие поля

- Owner - владелец SID
- DACL(Дискреционный ACL) - определяет какие пользователи могут выполнять определенные операции с объектом
- SACL(Системный ACL) - системный список управления доступом. В нем перечислены пользователи и операции, которые должны учитываться в журнале аудита безопасности

Когда процесс пытается получить доступ к объекту, его идентификатор сравнивается с идентификатором в системе защиты объекта.

11 UAC
В OC Windows существует встроенный компонент контроля учетных записей пользователя - User Account Control

UAC запрашивает подтверждение действий которые требуют наличие прав администратора. Делается в целях защиты от несанкционированного использования компьютера

Благодаря этому UAC помогает предотвратить:

- Запуск вредоносного ПО
- Автоматическую установку неавторизованных приложений
- Непреднамеренные изменения системных параметров и другие нелегитимные действия

При этом в ОС Windows существует несколько легальных способов повысить привилегии пользователя в рамках сеанса. Рассмотрим их подробнее, чтобы понимать каким образом потенциальный злоумышленник может ими воспользоваться:

1. Повышение прав с помощью утилиты RUNAS.exe
	Команду RUNAS используют для запуска приложений под учетной записью пользователя, имя которого передается в качестве параметра командной строки
2. Запуск исполняемого файла от имени другого пользователя из проводника Windows
	Чтобы в контекстном меню появилась опция "Запуск от имени другого пользователя" нужно нажать клавишу shift а затем нажать правой кнопкой мыши по иконке исполняемого файла.
3. Запуск исполняемого файла от имена администратора из проводника Windows с вводом учетных данных администратора
	Появляется при нажатии запуск от имени администратора

При использовании последних двух способов в системе запустится окно, которое уведомляет о попытке запуска нового процесса. В нем пользователю предложат ввести учетные данные с необходимыми правами, если у текущей учетной записи они отсутствуют

Процедура повышения привилегий через UAC производится в процессе consent.exe данный процесс представляет собой оконное приложение где пользователь вводит логин и пароль администратора. Процесс consent.exe передает данные на локальную подсистему аутентификации LSASS, которая принимает конечное решение - можно ли пользователю повысить свои привилегии или нет

# Реестр

Для хранения настроек и параметров операционной системы а также информации о программном обеспечении и оборудовании используется системный Реестр Windows. Он представляет собой иерархическую базу данных

Основным средством просмотра и редактирования записей служит встроенная в Windows утилита Regedit - редактор реестра. 


> [!NOTE] Системный Реестр
> Это иерархическая структура которая используется для хранения настроек ОС

![[Pasted image 20260623162839.png]]

Верхний уровень иерархии состоит из разделов, каждый из которых может содержать вложенные подразделы, а также параметры. Именно в параметрах хранится основное содержимое реестра, а разделы группируют схожие по назначению параметры

Часто для обозначения реестра используют термины ветки реестра и кусты

Кустами обычно называют разделы верхнего уровня, а иногда и вложенного в него уровня, например, `HKEY_LOCAL_MACHINE` и `HKEY_LOCAL_MACHINE\SAM` А ветками входящие в них структуры

Стандартные кусты реестра:

1 **HKEY_CURRENT_USER** - является корневым для данных конфигурации пользователя, вошедшего в систему в настоящий момент
	Здесь хранятся папки пользователя, цвета экрана и параметры панели управления. Эти сведения сопоставлены с профилем пользователя
	
	Вместо полного названия раздела иногда употребляется аббревиатура HKCU
	

2 **HKEY_USERS** - содержит все активные загруженные профили пользователей компьютера. Раздел HKEY_CURRENT_USER является подразделом раздела HKEY_USERS 
	Вместо полного названия раздела иногда так же используется аббревиатура HKU

3 **HKEY_LOCAL_MACHINE** - содержит параметры конфигурации относящиеся к данному АРМ(для всех пользователей). Наиболее интересным разделом является Software, который включает в себя настройки всех установленных в системе приложений
	Сокращенно раздел называют HKLM

4 **HKEY_CLASSES_ROOT** - хранит информацию об установленных программах. Например ассоциации файлов (ассоциированные программы для расширений файлов) и ярлыки для приложений.
	Хранящиеся здесь сведения позволяют выполнять необходимые программы при открытии файла с использованием проводника. Начиная с Windows 2000 эти сведения хранятся как в **HKEY_LOCAL_MACHINE**, так и в **HKEY_CURRENT_USER**.
	
	Вместо полного имени раздела иногда используется аббревиатура HKCR
	
5 **HKEY_LOCAL_MACHINE\Software\Classes** - содержит параметры по умолчанию, которые относятся ко всем пользователям локального компьютера. Для доступа к нему необходимы права администратора системы.

6 **HKEY_CURRENT_CONFIG** - содержит сведения о профиле оборудования, которое используется локальными компьютером при запуске системы

Получается что если пользователь изменит обои рабочего стола, информация об этом будет занесена в реестр Windows. При следующей загрузке операционной системы данные будут считаны их реестра и на рабочем столе отобразится нужное изображение

Каждая ветка реестра имеет свое значение, и некоторые из них могут оказаться критичными с точки зрения кибербезопасности. Рассмотрим несколько примеров

## **1. Ветки автозагрузки: \Run, \RunOnce, \RunServices**

В них злоумышленники могут добавлять свои программы, которые позволяют им запускать вредоносное ПО при каждом старте системы

![[Pasted image 20260623165039.png]]

## 2. Ветка автоматического входа в Windows: HKLM\Software\Microsoft\Windows NT\CurrentVersion\Winlogon

Если в параметр AutoAdminLoogon записать значение "1", в параметре DefaultUserName указать имя пользователя а в DefaultPassword его пароль, то пользователь сможет входить в Windows автоматически без ввода логина и пароля

![[Pasted image 20260623165439.png]]

## 3. Разрешение или запрет записи на внешние usb-носители

Для управления запретом потребуется ветка **HKLM\System\CurrentControlSet\Control**

В ней следует создать раздел StorageDevicePolicies, а затем сформировать в нем новый параметр WriteProtect с типом DWORD. Значение "1" для WriteProtect включит запрет на запись а "0" отключит его. Чтобы изменения вступили в силу нужно перезагрузить компьютер

![[Pasted image 20260623165719.png]]

Основные файлы которые отвечают за формирование реестра, хранятся в папке `%SystemRoot%\System32\Config`

Обычно это `C:\Windows\System32\Config\`, но в зависимости от ОС их состав может отличаться

Файл хранящий личные настройки пользователя "скрыт" в папке соответствующей учетной записи в **C:\Documents and Settings\имя пользователя**. Так же файлы которые отвечают за пользовательские настройки могут храниться в 

- C:\Documents and Settings\%Username%\(Ntuser.dat)
    
- C:\Documents and Settings\%Username%\Local Settings\Application Data\Microsoft\Windows\ (UsrClass.dat)

Именно таким образов на системе хранится куст **HKEY_CURRENT_USER**.

Файл `NTUSER.dat` является полезным источником информации при проведении технического расследования инцидента ИБ. В нем содержится информация обо всех действиях пользователя, его конфигурации и даже история браузера

## Как связаны реестр и аутентификация

Информация о локальных пользователях системы хранится в ветке SAM, которая расположена в HKLM

Информация о сетевых пользователях хранится службой LSASS в разделе. Злоумышленник может попытаться получить доступ к сохраненным учетным данным выгрузив себе содержимое этих разделов

Так же стоит отметить, что в старых версиях Windows разрешалась аутентификация (HTTP Digest Authentication) с использованием протокола WDigest. Аутентификация с использованием этого протокола предполагает хранение и передачу пароля в открытом нешифрованном и нехэшированном виде

Современные версии Windows так же поддерживают данный метод аутентификации. По умолчанию он отключен, но злоумышленник может включить его его путем установки значения "1" в параметре `UseLogonCredential`, который находится в ветке реестра `HRLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\WDigest` 

Это изменение приведет к тому, что пароли пользователей работающих в системе будут храниться в открытом виде. А получить их можно будет путем изучения дампа памяти процесса lsass.exe

Ветка реестра `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon` позволяет настроить автоматическую аутентификацию пользователя без ввода пароля. Этот функционал реестра также может использоваться злоумышленником для получения доступа к системе
