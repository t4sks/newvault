
При тестировании Reflected и Stored XSS ключевая задача это определить контекст возникновения уязвимости.

- Местоположение внутри ответа, где появляются данные, контролируемые атакующим.
- Любая проверка ввода или иная обработка, которую приложение применяет к этим данным

# XSS между HTML тегами
Когда контекст XSS это текст между HTML тегами, вам нужно внедрить новые HTML теги, рассчитанные на запуск JavaScript
Некоторые полезные способы выполнить JavaScript

```html
<script>alert(document.domain)</script>
<img src=1 onerror=alert(1)>
```

# Пример: Lab: Reflected XSS into HTML context with most tags and attributes blocked
Необходимо обойти WAF, я начал с перебора возможных тегов, в итоге у меня получилось найти два рабочих тега, который я взял с XSS CheatSheet PortSwigger, в итоге это `<body>` и `<xss>`, далее попробовал все возможные атрибуты из того же cheatsheet, из интересных нашел следующий атрибут `onresize`, который указывает на смену размеров окна тогда выполнится произвольный javascript код, теперь используем наш exploit сервер, поэтому используем его с телом iframe, потому что мы можем встроить сайт в iframe и стригерить событие которое вызовется при изменении размеров окна, для этого используем следующий payload 

```html
<iframe src="https://web-security-academy.net/?search=%3Cbody%20onresize=print()%3E" onload="this.style.width='100px'"></iframe>
```

и используем url кодировку для пейлоада на сайт потому что таким образом она правильно отображается далее отправляем это victim и получаем что лабораторная решилась

# Lab: Reflected XSS into HTML context with all tags blocked except custom ones
Для решения находим что применяется кастомный тег и почти любой атрибут, видим что можем использовать любой атрибут, я попробовал следующие можно автоматически стригерить фокус за счет `autofocus`, при этом мы получаем что на нашем теге во время фокуса можно выполнить js код, для этого составляем следующее

```
<xss tabindex=1 onfocus=alert(document.cookie) autofocus>
```

далее так как мы получили уже рабочий пейлоад(который надо зашифровать в URL), который отдает xss, доставим его нашему victim. Для этого на сервер создаем следующее:

<script>location="https://0a47009103d4641a80fe0375002e00d3.web-security-academy.net/?search=%3c%78%73%73%20%74%61%62%69%6e%64%65%78%3d%31%20%6f%6e%66%6f%63%75%73%3d%61%6c%65%72%74%28%64%6f%63%75%6d%65%6e%74%2e%63%6f%6f%6b%69%65%29%20%61%75%74%6f%66%6f%63%75%73%3e"</script>

после чего получаем выполненную лабу

# XSS в атрибутах и HTML тегах
Когда контекст XSS внутри значения атрибута HTML тега иногда можно завершить значение атрибута закрыть тег и внедрить новый. Например:

```html
"><script>alert(document.domain)</script>
```

Чаще в такой ситуации угловые скобки блокируются или кодируются и ваш ввод не может вырваться из тега в котором находится. Если удается закрыть значение атрибута, обычно можно добавить новый атрибут, создающий контекст в котором мы можем добавлять новый обработчик события и использовать js. Например:

```
" autofocus onfocus=alert(document.domain) x="
```

Вышеуказанная полезная нагрузка создает событие onfocus которое выполнит JavaScript когда элемент получит фокус, а так же добавляет атрибут `autofocus`, чтобы попытаться автоматически вызвать событие `onfocus` без взаимодействия с пользователем. Наконец он добавляет `x="` для аккуратного восстановления последующей разметки
# Пример Lab: Reflected XSS into attribute with angle brackets HTML-encoded
Для решения необходимо найти в каком контексте возникает уязвимость, в лабе указано что что она должна быть в атрибуте, и контекст возникновения получается такой: 

```
<section class=blog-header>
	<h1>0 search results for '&quot; autofocus onfocus=alert(1) x&quot;'</h1>
	    <hr>
	        </section>
            <section class=search>
	            <form action=/ method=GET>
	                <input type=text placeholder='Search the blog...' name=search value="VALUE">
                    <button type=submit class=button>Search</button>
```

наш ввод подставляется в value без экранирования кавычек, поэтому может внедрить пейлоад как в примере

```
" autofocus onfocus=alert(document.domain) x="
```

В результате получаем сделанную лабораторную работу

Иногда контекст XSS это тип атрибута HTML тега который сам по себе может создавать необходимый js контекст. В таком случае можно выполнить JavaScript не завершая значение атрибута. Например если контекст XSS в атрибуте href тега anchor, вы можете использовать псевдопротокол `javascript` для выполнения скрипта, например:

```
<a href="javascript:alert(document.domain)">
```

Вы можете столкнуться  сайтами, которые кодируют угловые скобки, но все же позволяют добавлять атрибуты. Иногда такие инъекции возможны даже внутри тегов, которые обычно не инициируют события автоматически,  например в теге `canonical`. Вы можете эксплуатировать это поведение с помощью access keys и взаимодействия пользователя в Chrome. Access keys позволяют назначать горячие клавиши, ссылающиеся на конкретный элемент. Атрибут `accesskey` позволяет определить букву, которая при нажатии в комбинации с другими клавишами(они различаются на разных платформах) вызовет события. В следующей лабораторной вы можете поэкспериментировать с access keys и эксплуатировать тег `canonical`
# Пример Lab: Reflected XSS in canonical link tag
Нужно найти на главной странице куда попадает пользовательский ввод в рамках ссылки, получаем наличие следующих строчек кода: 

```html
<link rel="canonical" href='[https://0a83009d03b8721280980de700a80075.web-security-academy.net/?](https://0a83009d03b8721280980de700a80075.web-security-academy.net/?)'>
```

далее так как наш ввод попадает именно туда, мы можем использовать это чтобы выйти за пределы атрибута и создать свои для этого используем примерно следующее

```
%27accesskey=%27x%27onclick=%27alert(1)
```

и нажимаем alt+x после чего нам засчитает выполнение лабораторной работы
