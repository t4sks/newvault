
# Способы выполнения JavaScript
Получив контроль над HTML, вы можете выполнять JavaScript несколькими способами

Самый распространенный это использовать тег `<script>` однако одним из его недостатков является то, что его легко идентифицирует веб браузер (Web Application Firewall, WAF). Другой недостаток заключается в том, что он не работает в контексте `InnerHTML`(Специфика HTML5 блокирует исполнение script через innerHTML поэтому нужны другие способы обработки)

Помимо `<script>` мы так же можем использовать другие теги в сочетании со встроенными обработчиками событий для выполнения кода. Например:

```
<img src="qweqwe" onerror="alert(1)">
```

Этот код загружает несуществующее изображение и использует событие `onerror` для выполнения кода

На самом деле, многие люди используют `x`  в качестве `src` потому что его легко писать и запоминать. Обычно путь `x` не существует но если он существует, то `onerror` не сработает. Поэтому есть шутка, что вы можете разместить изображение с именем `x` в корневом каталоге сайта и некоторые злоумышленники могут не обнаружить уязвимость XSS

Помимо `onerror`, можно использовать любой обработчик событий. Например:

```
<button onclick="alert(1)">Click me, please</button>
```

Нажатие кнопки вызовет сообщение, однако отличие этого метода заключается в том, что пользователь должен выполнить определенное действие, чтобы активировать XSS, например, нажать кнопку. В предыдущем примере с тегом `img` пользователю ничего не нужно делать и XSS сработает

Для более коротко кода можно использовать событие `onload` в `svg`

```
<svg onload="alert(1)">
```

Немного дополнительной информации в HTML кавычки `"` для значений атрибутов не обязательны. Если в вашем содержимом нет пробелов, вы можете их удалить без проблем. Даже между тегами и атрибутами можно заменить на `/` Таким образом код для `svg` можно написать так

```
<svg/onload=alert(1)>
```

Для создания полезной нагрузки XSS не требуется пробелы или кавычки

Часто используемые обработчики событий включают:
1. onerror - срабатывает когда ресурс не загрузился, пример:

```
<img src=x onerror=alert(1)>
```

браузер пытается загрузить изображение `x` не находит, вызывает `onerror` Работает с `<img> <video> <audio> <source> <object>` намеренно указываем невалидный `src` чтобы гарантировать срабатываение

---
2. onload -  срабатывает когда элемент успешно загрузился. Противоположность `onerror`

```
<svg onload=alert(1)>
```

SVG не требует загрузки внешнего ресурса - браузер парсит элемент, он готов, `onload` срабатывает мгновенно. Так же работает с `<body>`, `<iframe>`, `<img>(если src валидный)` 

---
3. onfocus - срабатывает когда элемент получает фокус. Пример:

```
<input onfocus=alert(1) autofocus>
```

`autofocus` заставляет браузер автоматически поставить фокус на элемент при рендере. Без `autofocus` нужно, чтобы жертва кликнула на элемент или перешла табом. С `autofocus` происходит автоматическое выполнение. Можно так же форсировать через URL фрагмент:

```
<input id=x onfocus=alert(1)>
<!-- URL: page.html#x — браузер прокрутит к элементу и отдаст фокус -->
```

---
4. onblur - срабатывает когда элемент теряет фокус. Противоположность `onfocus`, пример:

```
<input autofocus onfocus="this.blur()" onblur=alert(1)>
```

элемент получает фокус через `autofocus` в `onfocus` вызывается `this.blur()`, элемент теряет фокус, срабатывает `onblur`. Цепочка делает выполнение автоматическим в реальных сценариях используется реже - `onfocus` с `autofocus` проще и надежнее

---
5. onanimationend - срабатывает при завершении CSS анимации. Пример 

```html
<style>@keyframes x{from{opacity:1}to{opacity:1}}</style>
<div style="animation:x 0.01s" onanimationend=alert(1)>test</div>
```

Атакующий определяет минимальную анимацию в 0.01 секунду, она мгновенно завершается, событие срабатывает. Ценность вектора в том что он позволяет обходить WAF. Большинство фильтров ищут `onerror`, `onload`, `onfocus`. `onanimationed` редко попадает в черные списки. Требует возможность инжектить и CSS и HTML

---
6. onclick - срабатывает при клике на элемент

```
<div onclick=alert(1)>Click me</div>
```

требует взаимодействия жертвы - она должна кликнуть. Импакт ниже потому что не автоматический. Атакующий компенсирует это делая кликабельный элемент визуально неизбежным растягивая его на весь экран

```
<div onclick=alert(1) style="position:fixed;top:0;left:0;width:100%;height:100%"></div>
```

---
7. onmouseenter - срабатывает когда курсор входит в область элемента

```
<div onmouseenter=alert(1) style="width:100%;height:100%;position:fixed;top:0;left:0"></div>
```

не требует клика, достаточно просто движения мыши. Растянутый на весь viewport элемент гарантирует срабатывание при любом движении. Преимущество перед onclick - порог взаимодействия ниже. Недостаток - не работает на мобильных устройствах без мыши, в отличие от `onfocus` с `autofocus`

Помимо этих обработчиков событий, начинаются с `on`, есть еще один способ выполнения кода, который могли видеть разработчики фронтенда

```
<a href=javascript:void(0)>Link</a>
```

это используется для того, чтобы элемент не реагировал на нажатие. Из этого примера видим что, для выполнения кода можно использовать href, например:

```
<a href=javascript:alert(1)>Link</a>
```

# XSS в различных сценариях и механизмы защиты
Обычно места куда можно внедрить вредоносный код называются точками внедрения

```html
<div>  Hello, <span id="name"></span></div>
<script>  const qs = new URLSearchParams(window.location.search)  const name = qs.get('name')  document.querySelector('#name').innerHTML = name
</script>
```

Точка внедрения находится в строке `document.querySelector('#name').innerHTML=name`
