Применение ограничений на то, кто или что имеет право выполнять действия или получать доступ к ресурсам, в контексте веб приложений контроль доступа зависит от аунтефикации и управления сеансами
**Вертикальное повышение привилегий** - когда пользователь без особых прав смог получить доступ к админской панели 
пример получения доступа путем изминения URL
```
https://insecure-website/admin #после получения доступа
https://insecure-website/robots.txt
```
Если админская панель в свободном доступе к ней можно легко получить доступ даже обычным перебором

---
**Контроль доступа основанный на параметрах**
Часто приложение хранит права пользователя как:
- Скрытое поле
- Файл Cookie
- Предварительный параметр строки запроса
И на основании этих параметров принимает решение как обрабатывать запросы пользователя
Пример:
```
https://insecure-website.com/login/home.jsp?admin=true
https://insecure-website.com/login/home.jsp?role=1
```

Повышение привилегий основанное на контроле доступа
Вертикальное - повышения с юзера до админа
Горизонтальное - переход от юзер к юзеру
Пример:
```
https://insecure-website.com/myaccount?id=123
```
меняем значение айди получаем другого пользователя
это пример: <mark style="background: #BBFABBA6;">insecure direct object reference (IDOR)</mark> - небезопасная прямая ссылка на объект
