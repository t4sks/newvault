> [!info] Определение
>Известна так же как Shell Injection, позволяет атакующему выполнять команды операционной системы на сервере на котором работает приложение и обычно полностью компроментировать приложение и все его данные. Часто атакующий может использовать такую уязвимость для компроментации другой хостинговой инфраструктуры и эксплуатируя доверительные отношения развить атаку на другие сервисы в организации

## Внедрение OS Command Injection
Рассмотрим следующий пример:
Приложение магазин позволяет пользователю посмотреть, есть ли товар в наличии в конкретном магазине и эта информация доступна по URL
```
https://insecure-website.com/stockStatus?productID=381&storeID=29
```
Чтобы предоставить сведения о наличии, приложению нужно опросить различные легаси системы, которые реализованы через вызов shell команды с идентификатором товара и магазина в качестве аргументов
```
stockreport.pl 381 29
```
Эта команда выводит статус наличия указанного товара, который возвращается пользователю. В приложении нет защиты от command injection, поэтому атакующий может отправить следующий ввод: `
```
& echo abobas &
```
если этот ввод отправить в параметре productID то команды будет такой
```
stockreport.pl & echo abobas & 29
```
так как & разделяет разные команды, в shell, то в результате будет выполняться 3 команды одна за другой
```
Error - productID was not provided // выполнена без ожидаемых аргументов
abobas // результат команды echo
29: command not found // аргумент выполнен как команда, это и вызвало ошибку
```
Размещение дополнительно разделителя команд & после внедренной команды полезно, поскольку отделяет внедренную команду от того, что следует после точки инъекции, что снижает вероятность того, что последующее предотвратит выполнение внедренной команды
