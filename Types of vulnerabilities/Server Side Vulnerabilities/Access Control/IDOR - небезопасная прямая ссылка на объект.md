> [!info] IDOR определение
> Это тип уязвимости контроля доступа, который возникает когда приложение напрямую использует введенные пользователем данные для доступа к объектам. Чаще уязвимость связана с горизонтальной эскалацией но может быть и вертикальной


# Примеры
Существует множество примеров когда контролируемые пользователем значения параметров напрямую используются для доступа к ресурсам или функциям

## Уязвимость IDOR с прямой ссылкой на объект базы данных
Веб сайт использует URL для доступа к странице аккаунта клиента, извлекая информацию из базы данных:
```
https://insecure-website.com/customer_account?customer_number=132355
```
Здесь номер клиента напрямую используется как идентификатор записи в запросах к бд. Если не применяются другие меры контроля, атакующий может просто изменить значение `customer_number`, обходя контроль доступа и просматривая записи других клиентов. Это пример уязвимости IDOR, которая приводит к горизонтальной эскалации привилегий
Атакующий может добиться горизонтальной и вертикальной эскалации, изменив пользователя на того у кого больше прав, при обходе контроля доступа. Другие варианты включают эксплуатацию утечки пароля или изменение параметров после попадания на страницу аккаунта пользователя

## Уязвимость IDOR с прямой ссылкой на статические файлы
IDOR часто возникает когда чувствительная информация расположена в статических файлах на файловой системе сервера. Например веб сайт может сохранять транскрипты сообщений чата на диск с инкрементными именами файлов и позволять пользователям получать их по URL вида
```
https://insecure-website.com/static/12144.txt
```
В такой ситуации мы можем просто изменить имя файла чтобы получить транскрипт созданный другим пользователем и потенциально получить учетные данные и другие конфиденциальные данные пользователя.
