> [!info] Определение
> Уязвимость помогает злоумышленнику читать произвольные файлы на сервере такие как:
> Код и данные
> Учетные данные
> Конфиденциальные файлы
> В некоторых случаях атакующий может иметь возможность записывать произвольные файлы на сервер, что позволяет изменять данные или поведение приложения и в итоге получить полный контроль над сервером

> [!warning] Пример такой атаки
```
https://insecure-website.com/loadImage?filename=../../etc/passwd #для машин на Linux

https://insecure-website.com/loadImage?filename=..\..\windiws\win.ini
```

#### Чтение произвольных файлов на сервере с помощью Path Traversal
Для примера рассмотрим приложение магазина которое загружает фото в `HTML` следующим образом:
```
<img src="/loadImage?filename=218.png">
```
URL `loadImage` принимает параметр `filename` и возвращает содержимое указанного файла, файлы изображений хранятся на диске по пути `/var/www/images`. Чтобы вернуть изображение приложение добавляет запрошенное имя файла к этой базовой директории и использует `API` файловой системы для чтения содержимого файла, по факту приложение читает из `/var/www/images/218.png` Это приложение не имеет защиты от `path traversal` атак, и как результат атакующий может изменить URL и получить доступ к чувствительной информации, например:
```
https://Shop.com/loadImage?filename=../../../etc/passwd
```
и приложение прочитает файл из 
```
/var/www/images/../../../etc/passwd
```
это для `Unix` систем, пример для `windows`
```
https://Shop.com/loadImage?filename=..\..\..\windows\win.ini
```

#### Примеры эксплуатации Path Traversal

Множество приложений где пользователь вводит что то в пути файлов имеет защиту от таких атак, но часто их можно обойти
**Пример 1:**
Возможно использовать абсолютный путь к файлу, например 
```
/etc/passwd
```
чтобы ссылаться на файл напрямую
**Пример 2:**
можно так же использовать вложенные последовательности обхода, такие как 
`.....//` или `....\/`, `..//..//`, `....//....//`
**Пример 3:**
В некоторых местах, например в `URL` или в параметре `filename` запроса `multipart/form-data`, веб сервера могут вырезать любые последовательности обхода каталогов до передачи ввода в приложение, и иногда можно обойти такую отчистку закодировав в `URL` символы `../` это даст `%2e%2e%2f` или даже дважды закодировав их в `URL` `%252e%252e%252f` также могут сработать различные нестандартные кодировки, такие как `..%c0%af` или `..%ef%bc%8f` 
**Пример 4:**
Так же приложение может требовать чтобы переданное имя файла начиналось с ожидаемого базового каталога например `/var/www/images`, тогда стоит включить этот базовый каталог и добавить соответствующую последовательность для обхода
```
filename=/var/www/images/../../../etc/passwd
```
**Пример 5:** 
Может быть требование особого расширения например `.png`  `.jpg`  и так далее, в этом случае можно использовать `%00` нулевой байт, чтобы завершить путь требуемого расширения:
```
filename=..//..//..//etc//passwd%00.png
```

#### Методы борьбы с Path traversal attack
Самый эффективный способ борьбы с такой атакой это не передавать ввод пользователя в API вовсе. Многие функции приложения, которые это осуществляют можно переписать чтобы обеспечить тоже поведение но более безопасным образом

Если избежать передачи пользовательского ввода в API файловой системы невозможно, то можно использовать два уровня защиты для снижения шанса реализации атаки
- Валидируем пользовательский ввод перед обработкой. Идеально это сравнивать ввод со списком разрешенных значений(whitelist), если это невозможно то следует убедится что ввод содержит только разрешенный набор символов, например буквенно-цифровые
- После проверки переданного ввода добавьте его к базовому каталогу и используйте API файловой системы платформы чтобы привести путь к канонической форме. Проверьте, что канонический путь начинается с заданного каталога
