

1. Вы получили шелл с правами пользователя user, файл /etc/shadow имеет следующие права:  
    -rw----rw- root user /etc/shadow

Можно ли повысить привилегии в таком случае? Если можно, то как? Если нельзя, опишите почему и есть ли способы обхода?

2. Какой будет ответ, если у пользователя user будет такой набор групп: user cdrom vboxusers docker, а разрешения у файла /etc/shadow будут такими?  
    -rw----rw- root adm /etc/shadow

1 На мой взгляд нельзя потому что обычно пользователь user принадлежит группе user а linux проверяет права поочередно, что если мы уже принадлежим группе user то у нас совсем нет прав на доступ к этому файлу, по поводу способов обхода можно сказать что если есть suid бинарники которые принадлежат любому другому пользователю, то можно попробовать использовать его, либо использовать какой нибудь уязвимый сервис например веб с возможностью получить rce или хотя бы lfi для чтения файла и брутфорса пароля root
2 во втором случае мы можем писать и читать потому что для файла мы others мы можем либо просто добавить новую строку в конец файла с uid 0 и зайти под этим пользователем либо попробовать заменить пароль рута, сгенерировав новый хэш для пароля
Есть еще вариант через docker, то есть мы можем управлять демоном docker а он всегда работает от root, мы можем создать такой контейнер который будет работать с файловой системой напрямую
 ```
 docker run --rm -v /:/localsystem -it --privileged ubuntu chroot /localsystem /bin/bash
 ```
 после чего получаем рута на основной машине
