2. Логическая ошибка проверки роли из токена а не из бд в функции: admin_required, то есть если мы сами выдали себе роль и валидно подписали утекшим секретом, то сервер это примет, потому что нет проверки роли на стороне сервера
Максимальный реальный риск:
Получение доступа к админскомму функционалу при получении валидного секрета

Шаги по эксплуатации, полезная нагрузка для реализации этого риска и пояснения к ней с фрагментами кода:
Берем сгенерированный токен из предыдущей уязвимости, и пробуем зайти например на `/api/admin/view`(или выполнить действие на любом другом эндпоинте где требуется авторизация)
```
curl "http://app.com/api/admin/view?file=something" -H "Cookie: token=valid.jwt.token"
```
После чего получим ответ в виде файла или файл не найден если такого файла нет

Рекомендации по устранению, необходимые замены в коде и комментарий, каким образом они обеспечат защиту:
для закрытия этой дыры необходимо проверять отправленную роль в запросе с той что имеется в бд
```python
def admin_required(f):  
    @wraps(f)  
    @auth_required  
    def wrapper(*args, **kwargs):
	    provedRole = db.execute("SELECT role FROM users WHERE username == ?", (g.user.get("sub"),)).fetchone() 
        if not provedRole or provedRole["role"]!="admin":  
            return jsonify(error="admin access required"), 403  
        return f(*args, **kwargs)
    return wrapper
```
То есть просто добавим логику: если пользователя нет в бд или записанная в базе роль не админ тогда запрещаем доступ иначе разрешаем

3. Path Traversal при фильтрации файла, в функции `upload_file`, в этой строке  `filename = file.filename.replace("../", "").replace("..\\", "")`, функция удаляет паттерн `../` и `..\\`, но если используем `%2e%2e%2f` для выхода за директорию то сможем выйти за пределы директории при загрузке файла, а в view file мы можем прочитать любой файл с помощью того же path traversal

Максимальный реальный риск:
Чтение любых файлов на сервере к котором процесс имеет доступ

Рекомендации по устранению, необходимые замены в коде и комментарий, каким образом они обеспечат защиту:
необходимо исправлять две функции это upload_file и view_file, я бы наверное 

```python
@app.route("/api/admin/upload", methods=["POST"])  
@admin_required  
@csrf_protect  
def upload_file():  
    files = []  
    try:  
        files = os.listdir(UPLOAD_FOLDER)  
    except:  
        pass  
  
    if "file" not in request.files: # слабая проверка по блэк листу  
        return jsonify(error="no file selected"), 400  
  
    file = request.files["file"]  
  
    if file.filename == "":  
        return jsonify(error="filename is empty"), 400  
  
    if not is_allowed_file(file.filename):  
        return jsonify(error="file extension not allowed"), 400  
  
    filename = file.filename.replace("../", "").replace("..\\", "")   
  
    save_path = os.path.join(UPLOAD_FOLDER, filename)  
    file.save(save_path)  
  
    return jsonify({"message": "file has been successfully uploaded"}), 200  
  
  
@app.route("/api/admin/view", methods=["GET"])  
@admin_required  
def view_file():  
    files = []  
    try:  
        files = os.listdir(UPLOAD_FOLDER)  
    except:  
        pass  
  
    filename = request.args.get("file", "")  
  
    if not filename:  
        return jsonify(error="no file name specified"), 400  
  
    filename = filename.replace("../", "").replace("..\\", "")  
    filepath = os.path.join(UPLOAD_FOLDER, filename)  
  
    try:  
        with open(filepath, "r", encoding="utf-8", errors="ignore") as f:  
            content = f.read()  
            result = {"ok": True, "message": content}  
  
        return jsonify(**result)  
  
    except FileNotFoundError:  
        return jsonify(error="file not found"), 400  
  
    except Exception as e:  
        return jsonify(error=f"error reading file {str(e)}"), 400
```
