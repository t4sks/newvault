Set-Cookie для установки новых значений куки в браузере, 
пример
```
Set-Cookie: session=12345;
```
Дополнительные атрибуты заголовка
`Secure` - указывает браузеру что куки могут передаваться только по https, если есть ошибки сертификата или используется http то cookie  не будут передаваться
`HTTPOnly` - указывает браузеру что значение cookie не может быть прочитано JavaScript-кодом на стороне клиента
`Expire`- указывает браузеру когда значение cookie больше не будет действительным и должно быть удалено
`SameSite` - указывает браузеру может ли cookie передаваться в кросс-сайтовых запросах чтобы защититься от атак CSRF
Ключевой момент в том что браузер сам решает когда определнное значение cookie будет отправлено с запросом. Проанализировав домен и аттрибуты Cookie браузер принимает это решение без дополнительного клиентского JavaScript кода

Управление на основе токенов
Вместо автоматических функций управления cookie оно полагается на код на стороне клиента для выполнения процесса, после аутентификации веб приложение предоставляет токен в теле запроса с помощью JavaScript-кода н а стороне клиента и этот токен сохраняется в LocalStorage браузера. 
Когда выполняется новый запрос JavaScript-код должен загрузить токен из хранилища и прикрепить как заголовок Authorization: Bearer однако поскольку мы не используем встроенные функции управления coolie  в браузере это "дикий запад" где допустимо все. Существуют стандарты но на практике ничего по настоящему не заставляет их строго соблюдать.
