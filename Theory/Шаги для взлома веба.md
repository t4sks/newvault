- Общая разведка сайта.  
    — Посмотри сайт целиком. Через расширения (например, Wappalyzer) или вручную найди подсказки о языках и фреймворках. Wappalyzer не всегда даёт 100% точность.  
    — Перехвати ответ сервера в Burp — заголовки `Server`, `X-Powered-By` и т.п. дают информацию о стеке.  
    — Ищи вёрстки векторы атаки, например страницу загрузки файлов.
    
- Детальная инспекция точки загрузки.  
    — Проверь клиентские скрипты — есть ли клиентская фильтрация и как она работает (это поддаётся контролю с твоей машины).
    
- Сделай «невинную» загрузку.  
    — Посмотри, как к ней можно получить доступ: по прямому URL в папке uploads, встроена ли она в страницу, какая схема именования файлов. Если местоположение не очевидно, используй Gobuster. Этот шаг важен: даёт эталонный «принимаемый» файл для дальнейших тестов.
    
- Полезная опция Gobuster: `-x`.  
    — С `-x php,txt,html` Gobuster будет добавлять `.php`, `.txt`, `.html` к каждому слову из словаря — полезно, если сервер переименовывает загружаемые файлы.
    
- Попытка загрузки вредоносного файла.  
    — Обойди клиентские фильтры (шаг 2). Ожидай, что сервер остановит загрузку — сообщение об ошибке подскажет следующее направление.
    
- Как определить тип серверного фильтра (если загрузка блокируется):
- — Если можно загрузить файл с полностью несуществующим расширением (например `testingimage.invalidfileextension`), вероятно, сервер использует чёрный список расширений. Если такая загрузка не проходит — фильтр работает по белому списку.  
— Попробуй заново загрузить «невинный» файл, но предварительно изменить его «magic number» на тот, что должен фильтроваться. Если загрузка падает — есть проверка по magic number.  
— Аналогично: перехвати в Burp запрос и сменяй MIME (`Content-Type`) на фильтруемый; если загрузка блокируется — сервер фильтрует по MIME.  
— Для фильтров по длине файла загружай файлы всё большего размера, пока не встретишь ограничение — так узнаешь допустимый предел. Иногда сервер прямо указывает лимит в сообщении. Имей в виду: малый лимит размера может помешать загрузить обратный шелл.
